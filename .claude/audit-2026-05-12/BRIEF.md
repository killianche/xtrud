# UX/UI Audit — общий бриф для агентов

## Продукт

**xtrud** — маркетплейс мастеров и клиентов **в Республике Ингушетия**. Клиент находит мастера (категория → поиск → профиль → заказ → чат → отзыв), мастер получает заказы и ведёт переписку.

**ОБЯЗАТЕЛЬНО прочитай `PRODUCT_CONTEXT.md` в корне репозитория** перед началом аудита. Там — что мы строим, на кого ровняемся по функционалу (Profi.ru, YouDo, Avito Услуги, Яндекс.Услуги, TaskRabbit, Thumbtack, Bark, Airbnb, Uber), что мы **НЕ** делаем (scope guard), и региональная специфика.

Любая рекомендация в аудите должна:
1. Опираться на функциональные референсы из `PRODUCT_CONTEXT.md` (минимум 2 платформы, желательно одна RU + одна global).
2. Не выходить за scope guard (нет эскроу, нет доставки товаров, нет AI-генерации, нет долгосрочных контрактов).
3. Учитывать гео: рынок Ингушетии маленький, репутация важнее формальной верификации, наличные + СБП.

## Платформы — приоритет

1. **iOS + Android** (Expo + React Native + Expo Router) — это **главное**, всё проектируется mobile-first.
2. **Web** (Expo Web export через тот же код) — должен работать как полноценное web-приложение.

**ВАЖНО (уточнение от 2026-05-12):**
- Веб-дизайн **может и должен отличаться** от мобильного. Не «то же самое, растянутое до 1440px». На вебе — свои паттерны: top-nav вместо bottom-tabs, sidebar layout вместо stacked, multi-column на дашбордах, hover-стейты, keyboard-first навигация, breadcrumbs.
- У каждой платформы могут быть **свои настройки**: dark/light на iOS — system-driven, на web — toggle в header.
- Любая рекомендация по экрану должна явно делиться: «на мобайле так / на вебе иначе». Если решение одинаковое — явно писать «работает одинаково на обеих платформах, потому что [причина]».

## Темы — light + dark, обязательно обе

**ВАЖНО (уточнение от 2026-05-12):** проект поддерживает **обе темы** — light и dark. Для каждой находки:
- Подумай, как это будет в **dark mode** (контраст, surface-уровни, иконки).
- `DESIGN.md` сейчас в основном описывает light. Где dark-варианта токенов нет (например, тёмный `surface-card` или dark-вариант `pricing-tier-card`) — это пробел, отметить в кросс-экранных паттернах.
- На вебе пользователь должен иметь видимый theme-toggle. На мобайле — следовать системной теме (default), плюс override в настройках.

## Дизайн-направление

Цель — **минималистичный, качественный, Cal.com-inspired**. Источник истины: `DESIGN.md` в корне проекта (542 строки, поставлен через `npx getdesign@latest add cal`).

Кратко:
- Белый canvas (#ffffff), чёрные primary CTA (#111111).
- Cal Sans (display) + Inter (body/UI).
- Cards `rounded-lg` (12px), buttons `rounded-md` (8px), pills для nav-групп.
- Карточки на сером (#f5f5f5) или белом, без визуального шума.
- Тёмный footer (#101010) — единственная тёмная зона на светлых страницах.
- Generous whitespace, плотность низкая, иерархия за счёт типографики.

## Что НЕ так с прежними аудитами

`AUDIT.md`, `PRODUCT_BLINDSPOTS.md`, `COMPETITOR_INSIGHTS.md` — сделаны старым агентом «по памяти». Много общих фраз, мало конкретики, не привязаны к новому Cal.com-направлению. Этот аудит должен быть лучше: **конкретные референсы → конкретные правки**.

## Стек, который нужно учитывать

- Expo SDK 54 + Expo Router v6, RN 0.81 (new architecture).
- NativeWind 4 + Tailwind 3.4 (через CSS-vars для тем).
- TanStack Query 5 (server state) + Zustand (client/theme).
- React Hook Form 7 + Zod 3 (формы).
- Supabase backend + RLS, авторизация через телефон/OTP.
- Inter из @expo-google-fonts, иконки lucide-react-native.
- Light + dark темы (в DESIGN.md тёмная тема пока не прописана детально — это можно отметить как блокер).

Любая рекомендация должна быть **реализуема в этом стеке**. Не предлагать «давайте поставим Tailwind UI» — у нас RN, там нет HTML.

## Что искать на каждом экране

Для каждого экрана своей группы агент проходит по 4 «шляпам»:

### 1. Mobile UX Lead
- Куда ведёт навигация? Понятно ли куда тапать?
- Где живёт основное действие? Достаёт ли большой палец (thumb-zone bottom 1/3)?
- Что с жестами (swipe, pull-to-refresh, long-press)?
- Состояния: loading, empty, error, offline, success.
- Платформенные конвенции: iOS back-swipe, Android system back, safe-area, нотчи.

### 2. Visual Designer
- Соответствует ли экран `DESIGN.md`? (типографика, цвет, отступы, радиусы)
- Иерархия: что главное на экране? Видно ли это с первого взгляда?
- Плотность: не перегружен ли экран? Есть ли воздух?
- Touch-targets: ≥44pt для тапов?
- Консистентность с другими экранами проекта.

### 3. Conversion / Activation specialist
- Где пользователь может застрять или отвалиться?
- Онбординг: понятно ли, зачем шаг? Можно ли пропустить?
- Empty states: дают ли чёткий next step?
- CTA: один основной или конкуренция нескольких?
- Trust elements: социальное доказательство, счётчики, отзывы — где их не хватает?

### 4. Accessibility & Edge cases
- A11y: labels, hints, role, accessible navigation, screen reader.
- Большие шрифты (Dynamic Type на iOS).
- Контраст по WCAG AA.
- Что будет при долгих именах, длинных списках, плохой сети, отсутствии данных?
- Обработка ошибок — понятная для пользователя или техническая?

## Откуда брать референсы

**Lazyweb MCP сейчас недоступен в сессии** (загрузится после рестарта Claude Code). Использовать `WebFetch` для:

- **Прямых конкурентов** (рус. рынок мастеров): YouDo, Profi.ru, Avito Услуги, Яндекс.Услуги.
- **Глобальных аналогов**: TaskRabbit, Thumbtack, Bark, Fiverr, Upwork.
- **Эталонов мобильного UX**: Airbnb, Uber, Booking, Cash App, Revolut, Linear (не маркетплейс, но эталон чистоты).
- **Дизайн-референсов**: Mobbin (free pages), Cal.com (источник нашего направления), Linear, Notion mobile.

Минимум 3 референса на каждую крупную рекомендацию. Цитировать конкретно: «У TaskRabbit на экране карточки мастера снизу sticky-bar с ценой и кнопкой Book — у нас этого нет». Если референс — скрин с публичного URL, привести URL.

## Формат отчёта от агента

Каждый агент сохраняет свой отчёт в `.claude/audit-2026-05-12/<group>.md` со структурой:

```markdown
# Аудит: <Группа экранов>

## TL;DR
2-4 строки — самое главное, что нашли.

## Экраны в скоупе
- `app/(tabs)/orders/index.tsx` — Список заказов
- ...

## Референсы, на которые опирались
- TaskRabbit Browse Tasks: https://...
- ...

## Находки

### 🔴 Критично (ломает UX или конверсию)
1. **<Экран>**, **<проблема в одной строке>**
   - Что не так: ...
   - Референс: ... (скрин/URL)
   - Что сделать: добавить / убрать / изменить — конкретно
   - Сложность: S / M / L
   - Mobile / Web / Both

### 🟡 Важно (заметно ухудшает опыт)
[тот же формат]

### 🟢 Nice to have (полировка)
[тот же формат]

## Кросс-экранные паттерны
Что-то общее по всей группе — например, «empty states нет нигде, нужно добавить везде по шаблону X».

## Что отлично — НЕ трогать
Что уже хорошо сделано и должно остаться. Важно, чтобы команда не сломала это в спешке.
```

## Жёсткие запреты

- ❌ Не выдумывать референсы. Если URL не проверял — пиши «не проверено» или ищи реальный.
- ❌ Не предлагать «полностью переделать» — только конкретные правки.
- ❌ Не игнорировать `DESIGN.md` — все рекомендации **в его эстетике**.
- ❌ Не лезть в архитектуру кода — это UX/UI аудит, не код-ревью.
- ❌ Не трогать чужие группы экранов.

## Под отчёт = одна задача

Каждый агент работает только со своей группой экранов. В конце возвращает путь к своему файлу + 5–10 строк executive summary.
