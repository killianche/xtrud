# Lazyweb — референсы UI/UX (приоритет 1)

## Что это

[Lazyweb](https://www.lazyweb.com) — внешняя база из 1000+ скриншотов экранов реальных продакшен-приложений (онбординг, pricing, dashboards, settings, empty states и т.д.). Подключён в проект как MCP-плагин Claude Code (`lazyweb@lazyweb`).

Доступные MCP-инструменты:
- `lazyweb_health` — проверка соединения
- `lazyweb_search` — поиск экранов по текстовому запросу (например, `{"query":"pricing page","limit":5}`)
- (+ остальные инструменты сервера — посмотреть через listing MCP-tools)

## Когда использовать (обязательно)

Перед тем как **проектировать или существенно менять** любой UI-экран, **сначала** ищи референсы в Lazyweb. Это касается:

1. **Новых экранов** — онбординг, регистрация, главный фид, профиль, настройки, pricing, empty states, error states, success states.
2. **Редизайна существующих** — если экран ощущается «дёшево», переусложнённо или не работает по UX-метрикам.
3. **Сложных компонентов** — модалки, формы с многошаговой логикой, фильтры, таблицы, drawer-меню.
4. **Pricing / paywall / upsell** — здесь референсы особенно ценны, потому что конверсия чувствительна к деталям.

## Когда **не** использовать

- Тривиальные правки (поменять цвет кнопки, текст лейбла, отступ).
- Чисто бекенд-задачи (Supabase миграции, edge functions без UI).
- Когда дизайн уже задан макетом из `DESIGN.md` и задача — просто реализовать его как есть.

## Как использовать — рабочий цикл

1. **Сформулируй запрос конкретно.** Не `"login"`, а `"login screen with social auth and forgot password"`. Не `"settings"`, а `"account settings with billing section"`.
2. **Вызови `lazyweb_search`** с этим запросом, `limit` обычно 3–5.
3. **Изучи результаты.** Обрати внимание на:
   - иерархию информации (что вверху, что под фолдом),
   - плотность (сколько действий на экране),
   - copywriting (как сформулированы заголовки / CTA),
   - empty / loading / error states, если они есть в выдаче.
4. **Сформулируй вывод в ответе пользователю** — 2–4 пункта: какие паттерны заметил, что переиспользуем, что осознанно делаем иначе и почему.
5. **Только после этого** предлагай свой вариант экрана / компонента.

## Что НЕ делать

- **Не копируй экраны 1-в-1.** Это референс, а не исходник. Стиль и токены — из `DESIGN.md`.
- **Не игнорируй Lazyweb «потому что и так знаю как делать»** при проектировании важных экранов — пользователь подключил его именно ради этого этапа.
- **Не отправляй в Lazyweb приватные данные пользователя или содержимое БД** — это внешний сервис, туда уходят только текстовые запросы про UI.
- **Не коммить токен** `~/.lazyweb/lazyweb_mcp_token` в репозиторий. Файл живёт в `$HOME`, вне проекта — оставь так.

## Отчётность

В кратком отчёте в конце ответа фиксируй факт использования Lazyweb, если он был:
- «Использовал Lazyweb: искал `<запрос>`, посмотрел N экранов, переиспользовал паттерны X/Y.»

Если для дизайн-задачи Lazyweb **не** использовался — поясни почему (тривиальная правка / уже есть макет в `DESIGN.md` / и т.п.).
