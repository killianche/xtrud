# Проверка результата

Работа считается сделанной после запущенной проверки с реальным выводом, а не после написания кода. Устройства у нас нет — всё, что видно только на iPhone, называй UNKNOWN, а не «проверено».

## Что запускать

- Код: `npm run quality:check` (типы, токены, biome, 334+ тестов, каталог, версии) — после последней правки. Сервер: `cd server && npm run check`. Админка: `cd admin && npx tsc --noEmit -p . && npm run build`.
- Бандл: `npm run ios:bundle:check` (рост веса — с причиной).
- API вживую (без записи): `curl https://api.xtrud.pro/v2/health`; гость — `GET /v2/rest/<таблица>?select=...`; пользователь — вход тестовым аккаунтом Apple Review (`POST /v2/auth/login` с `{"login":"+79280000000","password":"Review2026xtrud"}`), токен в `Authorization: Bearer`. Проверять и запрет: не-админ на admin_* → 403, гость на запись → 401.
- База: только SELECT; изменения проверять пробным прогоном с ROLLBACK (навык xtrud-db-migration).
- Скриншоты владельца: вырезать нужную часть и смотреть крупно (`PIL crop`), сравнивать со старыми скриншотами в той же папке. Не делать вывод по уменьшенной картинке.

## Роли

UI — designer → реализация → xtrud-qa; доступ и база — xtrud-security; крупное — xtrud-reviewer. Отчёт агента не истина: ключевые утверждения перепроверить самому (агенты ошибались: «realtime мёртв», «оффлайна нет нигде», «72 миграции»).

## Ловушки

- **Замер в неподходящий момент:** проверка доступности шла, пока сервер был выключен из-за оплаты, — выводы были неверными. Сначала убедись, что объект проверки жив.
- **Вывод без данных из сети владельца** («белые списки») оказался ложным. Без записи с его стороны — гипотеза, не причина.
- Настройка «применилась», но на iOS не работает (indicatorColor у NativeTabs — только Android). Проверяй в исходниках библиотеки, на какой платформе действует проп.
- Коммит «прошёл», а в нём только удаления: после `git add` смотри `git diff --cached --stat`, а после коммита — `git show --stat HEAD`.
