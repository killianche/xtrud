# Review и E2E accounts — правила без секретов

> Этот файл намеренно не содержит email, телефонов, паролей или персональных
> данных. Git не является хранилищем секретов.

## Актуальная авторизация

- Регистрация: телефон + email + пароль.
- Вход: email или телефон + пароль.
- Восстановление: по email.
- SMS/OTP в актуальном production flow нет.

## Store review account

App Review использует отдельный production-аккаунт клиента:

- Login: `[PASSWORD_MANAGER: xtrud/store-review/client-login]`
- Password: `[PASSWORD_MANAGER: xtrud/store-review/client-password]`

Значения в password manager и store console должны совпадать. Сам аккаунт должен
быть подтверждён, иметь завершённый клиентский профиль и только синтетические
данные. Review account не является demo bypass и не должен зависеть от
специального кода, OTP или заранее известного общего пароля.

## Обязательная внешняя ротация

В прошлых ревизиях этого репозитория были закоммичены реальные review
credentials и персональные контакты. Их удаление из HEAD не удаляет копии из
истории, локальных clone, CI logs или ранее созданных артефактов.

До следующего store submit владелец release обязан:

1. изменить пароль аккаунта во внешней auth-системе;
2. заменить логин/телефон, если риск требует полной смены идентификатора;
3. обновить password manager и обе store consoles;
4. убедиться, что прежние значения не авторизуют;
5. завершить активные сессии старого аккаунта/пароля;
6. записать дату и исполнителя в закрытом release ticket.

Ротация не может быть заменена очисткой текущего файла или переписыванием Git
history.

## Maestro credentials

Текущие Maestro-сценарии используют только переменные окружения:

- `E2E_LOGIN` — login отдельного client review/test account;
- `E2E_PASSWORD` — его пароль.

Загрузить значения в shell следует через утверждённый password-manager CLI или
временную локальную сессию, не через `.env` в репозитории. Пример запуска без
печати значений:

```bash
maestro test \
  --env E2E_LOGIN="$E2E_LOGIN" \
  --env E2E_PASSWORD="$E2E_PASSWORD" \
  .maestro/authenticated-smoke.yaml
```

Guest smoke не требует credentials:

```bash
maestro test .maestro/smoke.yaml
```

Сценарии read-only: они не создают и не редактируют заказы, не отправляют
отклики и не изменяют профиль. Для мутационных проверок использовать отдельный
ручной test plan и предназначенный для этого набор синтетических данных.

## Требования к review/test account

- отдельный от личных и owner/admin аккаунтов;
- роль клиента, чтобы read-only smoke мог открыть «Мои заказы»;
- завершённый onboarding и подтверждённый email;
- никакого реального имени, телефона, аватара, адреса, фото или заказа;
- пароль уникален для xtrud и хранится только в password manager;
- lifecycle управляется владельцем release: создание, ротация, блокировка,
  удаление после согласованного retention period;
- доступность проверяется перед каждым submit с чистого устройства.

## Demo/preview и production

Preview-данные могут быть синтетическими и предназначены только для внутренней
демонстрации. Они не должны вводить в продукт чат, SMS, стадии сделки или иные
удалённые сценарии.

Production-сборка обязана иметь demo mode выключенным. Store review выполняется
на обычной production-авторизации с account из password manager. Запрещено:

- коммитить demo/review credentials или реальные PII;
- использовать общий статический пароль для нескольких ролей;
- размещать секреты в YAML, скриншотах, issue, commit message или CI log;
- seed'ить production из документации или локальных E2E-файлов;
- использовать owner/admin account для App Review;
- просить ревьюера вводить OTP, которого нет в актуальном продукте.
