## TL;DR

**xtrud — маркетплейс услуг (мастера ↔ клиенты) для Республики Ингушетия.** Модель — **доска объявлений (classifieds)**: клиент создаёт заказ → мастера откликаются (сообщение + цена) → клиент сам **звонит / пишет в WhatsApp** выбранному мастеру → после работы оставляет отзыв. Мастер заводит профиль (категории, портфолио, прайс, опыт, зоны работы), видит входящие заказы, откликается.

> ⚠️ **Без in-app чата и без lifecycle сделки** (нет «клиент выбрал мастера / в работе / подтверждение / спор») — это упрощённая модель с 2026-05-20. Номер клиента всегда скрыт, инициатор контакта — клиент. Полная актуальная картина — CLAUDE.md «🧭 Актуальная модель продукта» + `docs/SIMPLE_FLOW.md`.

**Платформы:** iOS + Android (главное) + Web (полноценный, не «адаптив телефона»). Одна Expo-кодовая база.

**Регион:** старт — Республика Ингушетия (Магас, Назрань). Расширение — другие регионы СКФО, потом РФ.

## Пользователи и роли

- **Клиент** — ищет мастера. Создаёт заказ (категория + описание + бюджет + срок + город/район), смотрит карточки, переписывается, выбирает, оставляет отзыв.
- **Мастер** — оказывает услугу. Заводит профиль с категориями, портфолио (фото работ), услугами и прайсом, опытом, радиусом выезда. Получает входящие заявки + ленту открытых заказов. Откликается, переписывается, выполняет, получает отзыв.
- **Админ** — пока минимальный (модерация портфолио, категорийные обложки). Не приоритет.

Один аккаунт = одна роль (на старте). Переключение ролей — отложенный кейс.

## Главные пользовательские сценарии (happy paths)

### Клиент
1. **Поиск мастера в категории** — таб «Главная» → категория → список мастеров → карточка → чат / заказ.
2. **Создать заказ-объявление** — таб «Заказы» → «Новый заказ» → визард (категория + описание + бюджет + срок + город) → опубликовать → ждать откликов.
3. **Переписка** — таб «Чаты» → диалог с мастером → договорились → отметить «выполнено» → оставить отзыв.

### Мастер
1. **Онбординг** — телефон → OTP → «я мастер» → категории → профиль (фото, бio, опыт, радиус, город) → готово.
2. **Получить заявку** — лента открытых заказов в своей категории → откликнуться → переписка → выполнение → запрос отзыва.
3. **Редактировать профиль / портфолио** — таб «Профиль» → редактирование → загрузка фото работ.

## Что мы НЕ делаем (scope guard)

- ❌ **Эскроу / удержание денег на платформе** — деньги между сторонами напрямую (наличка / перевод). Платформа не процессит платежи.
- ❌ **Доставка товаров** — это не Avito Доставка, не Wildberries. Только услуги.
- ❌ **Глобальная фрилансер-платформа** — не Fiverr / Upwork. Локальный рынок физических услуг с выездом, не digital gigs.
- ❌ **Долгосрочные контракты / тендеры** — заказ = одна задача, не B2B-проект.
- ❌ **AI-генерация описаний / автоматический матчинг** — пока без AI-надстроек.

Если в аудите всплывает фича из этого списка — она вне scope, агент не предлагает.

## Функциональные референсы

Это **не список «у кого скопировать дизайн»** — это список «у кого правильно подсмотреть, как должен работать функционал». Дизайн у нас свой, Cal.com-inspired (см. `DESIGN.md`) + принципы ниже.

### ⭐ Главные четыре (на них и ровняемся)

Эти четыре платформы — **первичные референсы**. Каждая рекомендация в аудите должна опираться минимум на одну из этих четырёх (плюс при желании — на дополнительные). Остальные платформы в этом документе — второстепенный контекст, не основа.

| Платформа | Что берём (главное) |
|---|---|
| **Profi.ru** | Глубокая таксономия (категория → подкатегория → лист), верификация мастеров (паспорт + опыт), «специалисты напишут сами» (клиент описывает задачу — отклики приходят), отзывы привязаны к факту работы, ранжирование по релевантности + рейтингу |
| **Яндекс.Услуги (Яндекс Исполнители)** | Гео-карточка мастера (радиус выезда на мини-карте), прайс-индикатор «средняя цена за это в вашем городе», простой кабинет исполнителя с минимальным шумом, аккуратная типографика и плотность |
| **TaskRabbit** | Browse Taskers экран (визуально чистая сетка карточек), Tasker profile с почасовой ставкой и «выполнено X задач», in-context Book CTA, простой пошаговый request flow без визуального шума |
| **Thumbtack** | Pro detail page как образец «карточки исполнителя нового поколения»: большое фото, рейтинг + кол-во работ, FAQ от мастера, фотогалерея, trust-signals блоками; «Get matches» воронка заказа |

### Дополнительный контекст (не основа, но полезно цитировать)

| Платформа | Где может пригодиться |
|---|---|
| **YouDo, Avito Услуги** | RU-рынок, понимание ожиданий рус. пользователя (как формулируется CTA, бейджи доверия, время ответа) |
| **Airbnb** | Двусторонние отзывы, разделение Host profile (showcase) vs My account (settings), photo-grid портфолио, host onboarding flow |
| **Uber** | Driver carrier card на экране подтверждения заказа, in-app chat с шаблонами, post-trip rating modal |
| **Cal.com** | Источник **дизайна** (см. DESIGN.md). НЕ источник функционала. |

### 💎 Для конкретных фич — короткая мапа

- **Onboarding мастера** → Profi.ru мастер-кабинет + Яндекс Исполнители (минимум шагов до публикации) + Airbnb host onboarding (прогресс и возвратность).
- **Карточка мастера** → **Thumbtack pro detail** (главный референс) + TaskRabbit Tasker card.
- **Лента / каталог** → **TaskRabbit Browse Taskers** (главный референс) + Profi.ru каталог категории.
- **Создание заказа** → **TaskRabbit request flow** + Profi.ru «специалисты напишут сами».
- **Чат** → Telegram (базовые паттерны) + Thumbtack pro-customer chat (с шаблонами).
- **Портфолио мастера** → **Thumbtack photo gallery** + Airbnb host photo grid.
- **Отзывы** → Profi.ru (с подтверждением факта работы) + Airbnb двусторонние.

## Дизайн-принципы (обязательно учитывать в аудите)

Это не «как красиво», а **критерии оценки**: каждая рекомендация агента проходит через этот фильтр.

1. **Минимализм** — белый/светлый canvas, чёрные акцентные CTA (по `DESIGN.md`), низкая визуальная плотность, много воздуха. Не лепить кнопки в каждый угол.
2. **Классные фото — главный визуальный нерв.** Фото мастера и портфолио должны быть большими, качественными, аккуратно скомпонованными в grid/lightbox. На карточке мастера фото — не аватарка 40×40, а ощутимый блок (паттерн Thumbtack / Airbnb). Все upload-пайплайны должны давать пользователю инструмент сделать фото хорошим (crop, ratio, минимальное разрешение, аккуратные плейсхолдеры пока нет фото).
3. **Удобство** — главный сценарий доходит до результата за минимум тапов. На мобайле важные действия в thumb-zone. На вебе — keyboard accessible. Никаких «обязательных полей, которые можно было сделать опциональными».
4. **Скорость** — feed должен пролистываться плавно (используем FlashList), open масштабируется (skeleton-loaders, не белые экраны), картинки прогрессивно догружаются (expo-image с blurhash/placeholder), переходы 200–300мс.
5. **Современность** — типографика Cal Sans + Inter с правильным letter-spacing, мягкие радиусы (8/12/16), микро-анимации на интеракциях, dark + light темы одинаково аккуратные.
6. **Функциональность и грамотная инженерия** — каждый элемент на экране должен делать работу. Никаких декоративных блоков «для красоты», никаких полу-готовых состояний (мигающие плейсхолдеры, обрезанный текст, незаполненные пустые поля). Если кнопка есть — она работает на всех платформах одинаково; если поле есть — оно валидируется; если есть loading — оно не висит вечно; если есть ошибка — она читаемая. Дизайн без функциональности — это макет, а не продукт.

**Anti-pattern, которого избегаем:** «Avito-style» — много мелкого текста, цветные бейджи в карточке, баннеры рекламы внутри списка, лишние секции «возможно вам понравится». Это противоположность того, что мы строим.

## Региональная специфика (Ингушетия + СКФО)

- **Малый размер рынка** — все друг друга знают, репутация важнее формальной верификации. → Доверие через «рекомендация знакомого», возможность увидеть «общие контакты» (отложено, но иметь в виду в архитектуре).
- **Религиозный контекст** — некоторые услуги имеют гендерные ограничения (мастер-женщина для женщины-клиента и т.п.). Не реализуем сейчас, но в карточке мастера может быть отметка «работаю с женщинами/мужчинами/любыми».
- **Языковой контекст** — основной язык интерфейса русский. Ингушский — приоритет 2 (отложено).
- **Платёжный контекст** — наличные + СБП. Карты с MC/Visa — не приоритет.
- **Часовой пояс** — МСК. Бизнес-часы 9:00–22:00 МСК.

## Как использовать этот документ в аудите

- При оценке любого экрана агент должен задать вопрос: «как это решено в Profi.ru / Avito / YouDo? У TaskRabbit / Thumbtack / Airbnb?» — и привести 2–3 референса.
- Если рекомендация противоречит scope guard (см. «Что мы НЕ делаем») — её не предлагать.
- Если рекомендация работает только в крупном городе (Москва / SF / NYC) и неприменима в Ингушетии — отметить как «отложить до расширения географии».
