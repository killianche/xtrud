## Новые правила и решения

- **Витрина мастера = N подборок, не «отчёт о моих откликах»** (`STATUS.md` § «Главная мастера = дискавери-витрина»). xtrud — classified-ads платформа, после отклика мастеру в продукте делать нечего. Главная = JTBD «найти работу», не «контролировать активность».
- **Объединение «отдельная сущность активные» + «отдельная сущность история» на ОДНОМ экране без табов** (`MyResponsesScreen`). Когда списки короткие (1-5 + 5-20), scroll читается легче чем табы. Linear «Issues + Projects» эталон. Если в будущем активных станет 20+ — стоит вернуть табы.
- **Один RPC обслуживает N витрин-секций через client-side фильтр** (`use-master-recommendations.ts`). Альтернатива (3 RPC с разными параметрами) усложнила бы инвалидацию и кэширование. Применимо когда подборки берут подмножество одного фида.

## Новые компоненты / паттерны

- **`useMasterRecommendations`** (`src/features/master-view/use-master-recommendations.ts`) — общий хук рекомендаций. Принимает `{ userId, filter, max }`. Возвращает `{ recommendations, isLoading, hasCategories }`. Использовать когда нужна client-side подвыборка из общего фида open-заказов по категориям мастера. НЕ использовать для серверной фильтрации (нет нового RPC).
- **`MasterUrgentTodaySection`** — обёртка над хуком с `filter='urgent'`. Использовать только на главной мастера (узкая выборка).
- **`MasterFreshTodaySection`** — обёртка с `filter='fresh_24h'`. Тоже только на главной.
- **`MyResponsesScreen`** (`app/(tabs)/orders/my-responses.tsx`) — единый экран откликов мастера. Использует `useMyResponses` + два предиката (`isActiveResponse`/`isHistoryResponse`). Если в будущем понадобится экран только-историй — `/orders/responses-history.tsx` всё ещё есть в репо (legacy, дублирует «История» из my-responses).
- **Pill-entry под `ScreenHeader`** (`/orders/search`) — паттерн compact navigation entry, который НЕ загромождает rightAction шапки. Использовать когда у экрана уже есть rightAction (Фильтры) и нужна дополнительная навигация.

## Anti-patterns обнаруженные в сессии

- **«Главная как to-do лист уже сделанного»** — раньше «Ваши отклики» висели на главной мастера. Это превращало главную в «отчёт о моей активности», а не в инструмент поиска. После отклика мастеру делать там нечего — он только ждёт звонка клиента. → Главная всегда должна служить главному JTBD пользователя (для мастера — поиск работы), а не быть свалкой всех его сущностей.
- **«Один длинный экран без сегментации»** — соблазн вынести все отклики (активные + историю) на один безымянный список. Но смысл «активный отклик» (ждёт результата) ≠ «закрытый отклик» (мёртвый). Разные ментальные модели → нужны явные секции с заголовками и счётчиками. Сделано в `MyResponsesScreen`.

## Anti-patterns (вечер)
- **Удаление enum-значения / колонок ради «чистоты»** — рискованно, если на них завязан журнал/триггеры. Если значение недостижимо и записей 0 — дешевле и безопаснее оставить как мёртвый остаток, чем переписывать зависимости. Так поступили со статусом `disputed`.
- **Тексты legal, описывающие несуществующую фичу** — privacy/terms описывали чат и споры, которых уже нет. Это вводит в заблуждение и опасно для App-Store-ревью. При удалении фичи проверять `app/legal/*` и строки разрешений в `app.json`.
