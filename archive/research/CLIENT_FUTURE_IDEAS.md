# Идеи для клиентской стороны (отдельный файл — не делаем сейчас)

> **Контекст:** руководитель сказал «На данный момент мы делаем сторону мастера, но если есть какие-то идеи для клиента, их просто запиши как задачу». Этот файл — копилка идей. Делаем когда вернёмся к клиентской стороне (после публичного запуска master-функционала).

## Источник идей

Из аудитов конкурентов ([RU_MASTER_AUDIT.md](RU_MASTER_AUDIT.md), [US_MASTER_AUDIT.md](US_MASTER_AUDIT.md), [SEARCH_AUDIT.md](SEARCH_AUDIT.md)) — отметил всё что относится к клиенту, чтобы не потерять.

---

## C1. Умный поиск услуг для клиента (P0-NEW для мастера, тут — для клиента)

**Что:** клиент в `/orders/new` или на главной вводит «камера» → получает «Видеонаблюдение и охрана» (через словарь синонимов из P0-NEW).

**Зачем:** клиент не знает наших точных названий категорий. «Камера», «холодильник», «протекает кран», «починить компьютер» — все эти слова должны вести к правильной L2/L3.

**Где:** `app/(tabs)/orders/category-select.tsx` (сейчас заглушка typeahead bottom-sheet — TASKS.md уже отмечает это).

**Связь:** P0-NEW делается для мастера в первую очередь, но 90% инфраструктуры (БД-таблица синонимов + RPC `search_services` + раскладка-фикс) — общая. Для клиента это будет переиспользование того же RPC.

---

## C2. Главная клиента — wizard «Что нужно сделать?»

**Эталон:** Яндекс Услуги (на главной — большой инпут «Что нужно сделать?» с автокомплитом).

**Что:** заменить главную клиента на единый search-input с подсказками популярных услуг → выбор → переход в `/orders/new` с предзаполненной категорией.

**Связь с C1:** требует умный поиск. Также из TASKS.md паттерн «Wizard» уже отмечен.

---

## C3. История заказов — Client Hub (Jobber pattern)

**Эталон:** Jobber Client Hub — клиент видит все свои заказы, чаты, отзывы в одном месте; может переоткрыть прошлый заказ для повторной услуги.

**Что:** в профиле клиента — раздел «Мои заказы» с историей + повторить + leave review post-fact.

---

## C4. Sample profile preview перед созданием заказа

**Эталон:** TaskRabbit, Thumbtack показывают «вот пример как выглядит мастер которого вы найдёте».

**Что:** на экране создания заказа, до публикации — рекомендованные мастера в этой L2 + город (превью карточек). Клиент видит «вот кто откликнётся».

**Зачем:** снижает страх «никто не откликнется». Конверсия вверх.

---

## C5. Pricing benchmark «обычно X-Y ₽» для клиента

**Эталон:** Thumbtack «Prices Page» — клиент видит средние цены на услугу в его регионе.

**Что:** при создании заказа в поле бюджета — подсказка «В Магасе обычно 1000-3000 ₽ за установку смесителя» (использует таблицу `pricing_benchmarks` или агрегат из `master_services` по L3+city).

**Зависимости:** требует наполнения `pricing_benchmarks` (часть P0-4 / P1-1).

---

## C6. Карта мастеров (PostGIS) для клиента

**Эталон:** Yandex Pro, Google Maps Services.

**Что:** клиент видит карту своего города/района с pin'ами мастеров (по `service_locations` мастера). Tap по pin'у → карточка мастера.

**Зависимости:** P1-3 (service area — multi-city + radius), P3-2 (PostGIS для master locations).

## C7. Push-уведомления для клиента

**Какие события (mirror N4 из master-side):**

| Событие | Когда |
|---|---|
| Мастер откликнулся на заказ | INSERT в `order_responses` для моего заказа |
| Мастер ответил в чате | INSERT в `messages` |
| Мастер отметил «работа выполнена» | UPDATE на `confirmed_done_by_master_at` |
| Напоминание оставить отзыв | Cron через 1 день после `completed` |
| Срок ответа мастеров истёк (24h) | Cron от `created_at` без откликов |

**Архитектура:** см. N4 — для клиента работает та же Edge Function `dispatch_notification`, разница только в наборе событий.

---

## C8. Анти-увод-в-Telegram (мягкая версия)

**Эталон:** TaskRabbit, Profi.ru.

**Что:** при попытке отправить в чате номер телефона/email/упоминание Telegram/WhatsApp до `confirmed` — мягкое предупреждение «Безопаснее общаться через xtrud, мы поможем при споре».

**Не блокировать**, как у Profi (они зарабатывают на лидах, у нас иначе) — только напоминание.

---

## C9. Dashboard клиента «Сколько вы тратите на услуги»

**Что:** агрегатор истории заказов клиента — сколько потратил, в каких категориях, средний рейтинг мастеров. Полезно для семейного бюджета.

**Низкий приоритет** — nice-to-have, не блокирует.

---

## C10. «Похожие заказы» при создании

**Что:** при наборе title заказа — подсказки похожих формулировок из истории «как другие клиенты формулировали такую задачу». Помогает менее опытным клиентам.

**Зависимости:** требует данных + ML-light (или просто LIKE по title с GIN-trigram).

---

## C11. Клиент может «пригласить мастера» точечно

**Эталон:** TaskRabbit invitation-based.

**Что:** клиент в каталоге мастеров находит конкретного мастера → «Пригласить на мой заказ» → push мастеру с прямой ссылкой.

**Связано с моделью лидов** (см. P1 в research/MASTER_ACCOUNT_PLAN.md).

---

## C12. Рейтинги клиента (двусторонние)

**Эталон:** Profi.ru, TaskRabbit двусторонние отзывы.

**Что:** не только мастер получает отзыв от клиента, но и клиент от мастера. У клиента появляется свой rating «5★ — платит вовремя, не отменяет».

**Польза:** мастера могут принимать решение «не отвечать на этого клиента, у него рейтинг 2★».

**Зависимости:** требует UI отзыва и поле `client_rating` в users или отдельной таблице.

---

## C13. Push на отметку «получено» для важных уведомлений

**Что:** некоторые уведомления (мастер отменил, отзыв) — должны иметь статус «прочитано». В `notification_history(user_id, event, body, sent_at, read_at)`. UI «1 непрочитанное».
