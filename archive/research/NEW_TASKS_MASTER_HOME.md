## N1. Убрать блок «Ваши категории» с master-главной

**Что:** на главном экране мастера видна секция «Ваши категории» с pill-чипами выбранных L2 + ссылка «Редактировать (5/5)».

**Почему убрать:** настройка профиля (категории, прайс, расписание) — это раздел «Профиль», не главная. На главной мастера должна быть **рабочая лента заказов**, а не дублирование настроек.

**Где:** [src/features/master-view/MasterHomeContent.tsx](../src/features/master-view/MasterHomeContent.tsx).

**Что должно остаться вместо:** входящие заказы, статус доступности, бейдж «3 из 5 откликов».

## N2. Убрать кнопку «+ Создать заказ» из master-режима

**Что:** в bottom-nav у мастера есть кнопка плюс (создать заказ). Это кнопка клиента.

**Почему убрать:** мастер не создаёт заказы, он на них откликается. Эта кнопка вводит в заблуждение и занимает место в навигации, которое может занять более полезная.

**Где:** проверить [src/components/TabBar.tsx](../src/components/TabBar.tsx) или layout `(tabs)/_layout.tsx` — есть ли разделение по `active_role`.

**Альтернатива:** для dual-role (мастер ↔ клиент в одном аккаунте) — кнопка «+» появляется только когда `active_role='client'`.

## N3. Добавить «Поиск заказов» для мастера

**Что:** мастер открывает раздел «Поиск заказов» → видит ленту всех активных (открытых, нераспределённых) заявок клиентов в его категориях/городе. Может откликнуться.

**Почему:** сейчас мастер видит только заказы во вкладке «Новые» — но если хочет проактивно поискать что-то по конкретной категории, фильтру района, бюджету — нет инструмента.

**Где:** новая кнопка в master-bottom-nav или на главной (вместо «+ Создать заказ» из N2).

**Как:**
- Лента подобная `/orders` (master view → таб «Новые»), но с расширенными фильтрами:
  - Конкретная L2/L3 категория (не только из «моих»)
  - Диапазон бюджета
  - Срочность
  - Город / район
- Сортировка: новые / срочные / дорогие
- Бейдж «3 из 5 откликов» — лимит виден сразу

**Связь с P0-NEW (умный поиск):** когда P0-NEW будет готов — search-input в этой ленте будет понимать «камера», синонимы, раскладку и матчить L3-услуги.

## N4. Спроектировать систему push-уведомлений (приложение + web)

**Контекст:** xtrud — Expo (iOS/Android приложение) + web. Нужны нативные push для мобилок и web push для браузера.

**Какие события триггерят push (для мастера):**

| Событие | Триггер | Действие при тапе |
|---|---|---|
| Новый заказ в моей категории+городе | `INSERT` в `orders` с matching `l2_id` + `city_id` | Открыть `/orders/[id]` |
| Клиент написал в чате | `INSERT` в `messages` | Открыть `/chats/[id]` |
| Меня выбрали (response.status='accepted') | `UPDATE` в `order_responses` | Открыть `/orders/[id]` |
| Клиент отменил заказ | `UPDATE orders.status='cancelled'` где я выбран | Открыть `/orders/[id]` |
| Клиент оставил отзыв | `INSERT` в `reviews` где target=я | Открыть `/master/[id]` (мой профиль с отзывами) |
| Напоминание о незавершённом заказе (reminder) | Cron-job через 3 дня после `confirmed` | Открыть `/orders/[id]` |
| Лимит откликов сброшен | Cron в 00:00 каждый день | Открыть `/orders` |

**Что НЕ триггерит push:**
- Просмотры профиля (слишком частое, шум)
- Каждое изменение моего профиля (мои действия)

**Архитектура:**
1. **Native:** `expo-notifications`. При первом запуске — request permission. Сохраняем FCM/APNs токен в `notification_tokens(user_id, token, platform, last_seen_at)`.
2. **Web:** Service Worker + Web Push API. Браузер запрашивает permission, токен в той же таблице с `platform='web'`.
3. **Backend:** trigger в БД на нужные события → call Edge Function `dispatch_notification` → она группирует токены по user_id и отправляет в FCM (Android+iOS) и Web Push (браузер).
4. **Quiet hours:** не слать push с 22:00 до 08:00 локального времени мастера (опц. настройка в профиле).
5. **Notification preferences:** мастер в настройках может выключить категории уведомлений (новые заказы / чат / выбор / отзывы).

**Что зависит от других решений:**
- Apple Developer Account ($99/год) — не заведён (см. отложенный блок плана).
- Firebase project — не настроен.
- Триггеры в БД (`notify_*`) — частично готовы, нужно проверить покрытие всех 7 событий выше.
- Edge Function `dispatch_notification` — **не существует**, нужно написать.

**Минимально жизнеспособная версия (без Apple Dev):**
- Web push через Service Worker (Notifications API + Push API).
- Браузер тестируется в preview уже сейчас.
- Native — отдельной фазой когда заведём Apple Dev и Firebase.

**Что надо добавить в [research/MASTER_ACCOUNT_PLAN.md](MASTER_ACCOUNT_PLAN.md):**
- Расширить блок «🕒 Push-уведомления» — конкретный список событий и архитектура.
- Добавить промежуточный шаг «Web Push на текущей фазе» — если хотим показывать уведомления в браузере без нативки.
