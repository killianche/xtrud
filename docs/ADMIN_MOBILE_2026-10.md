## 1. Что есть сейчас (FACT, код 2026-10-29)

- **Каркас — настольный.** 22 раздела в боковой панели (`admin/src/components/Shell.tsx`),
  на телефоне — выезжающая шторка во весь экран (скриншот владельца). Иконки
  повторяются и не несут смысла: звезда у «Аналитики», «Отзывов» и «Большого
  опыта»; флаг у «Жалоб», «Подозрительных» и «Скрытых заданий»; «люди» у
  «Людей», «Компаний» и «Команды».
- **Не приложение для «Домой».** В `admin/index.html` нет манифеста, иконки
  для iOS, service worker, `theme-color`, отступов под вырез — с экрана
  «Домой» откроется как вкладка Safari без уведомлений.
- **Уведомлений нет.** Сервер шлёт push только в приложение (APNs, FCM,
  RuStore — `server/src/push/`). Web Push (VAPID) нет вовсе. Сейчас о
  событиях владелец узнаёт только из внешнего монитора в Telegram (сбои).
- **Подтверждения через `window.prompt` / `window.confirm`** — 30 мест.
  На iPhone это серые системные окна без вариантов ответа: причину отказа
  паспорта приходится печатать вручную.
- **Задания.** Действия: «Скрыть задание» (`admin_hide_order`, 0175 → статус
  `cancelled`, `cancel_reason = 'moderation: …'`, автору уведомление
  `order_hidden`), «Скрыть тихо» (0231, автор не знает), «Вернуть в ленту»,
  «Тестовое», смена категории. **Отдельного «Отклонить: это не задание»
  нет, списка отклонённых нет**, удалить нельзя. В «Без категории» задание
  можно только отнести в категорию — отказать нельзя.
- **Паспорт и компания** — две независимые проверки: паспорт (0174, раздел
  «Паспорта») и компания (0245, раздел «Компании»: название, Instagram,
  WhatsApp; логотип не просят). В приложении обе строки лежат рядом в
  «Дополнительно» и **не зависят от типа** — частному мастеру предлагают
  компанию, компании — паспорт. Отсюда логотип в очереди паспортов.
- **Тип аккаунта** (`master_account_type`: `solo | brigade | company`) меняет
  только сам человек (`set_account_type`); у админа такого действия нет.
  В приложении два варианта: «Частный мастер» и «Компания»; `brigade` не
  используется.

## 2. Референсы

| Источник | Что берём |
|---|---|
| iOS: Почта, Напоминания, Настройки | Нижняя панель вкладок, крупный заголовок, свайп по строке для быстрого действия, шторка снизу для подтверждения |
| Shopify Admin (iOS) | Админка в кармане: «Главная» = что требует внимания, остальное — в «Ещё» |

| Авито / Profi.ru (модерация объявлений) | Отказ с готовой причиной из списка; автор видит причину и может исправить (UNKNOWN в деталях — по открытым правилам площадок) |

Скилы для работы: `apple-design`, `mobile-native` (PWA на iPhone),
`animate` / `review-animations`, `impeccable`, `web-design-guidelines`.

## 3. Предлагаемое решение

### 3.1. Каркас — приложение, а не сайт

Нижняя панель из 4 вкладок вместо 22 пунктов меню:

| Вкладка | Что внутри |
|---|---|
| **Входящие** (с числом) | Единая лента всего, что ждёт решения: жалобы, паспорта, компании, Instagram, «Большой опыт», звонки на восстановление, задания на проверке. Каждая карточка разбирается на месте: «Подтвердить» / «Отклонить» с готовыми причинами |
| **Задания** | Сегменты: На проверке · Опубликованы · Отклонённые · Скрытые тихо. Поиск |
| **Люди** | Поиск по имени и номеру; карточка человека со всем, что с ним связано, и действиями |
| **Ещё** | Аналитика, каталог, реклама, рассылка, журнал, команда, настройки, уведомления |

Плюс: манифест, иконка, тёмная и светлая тема по системе, отступы под вырез
и полоску «Домой», без масштабирования при вводе, тактильный отклик на
нажатие, подтверждения — шторкой снизу вместо `window.prompt`.

Визуальный язык: показываю **два направления на живых экранах**, владелец
выбирает (раздел 5, вопрос 6). Оба — по токенам и в обеих темах.

### 3.2. Задания: «это не задание»

- Новое действие **«Отклонить»** с причинами одним касанием: «Это реклама
  услуг, а не задание», «Дубль», «Запрещённая тема», «Недостаточно
  описания», «Другое…». Автору — уведомление с причиной, задание пропадает
  из ленты и падает в **«Отклонённые»** (с причиной, кто и когда), откуда
  можно вернуть.
- В «На проверке» (бывшее «Без категории») у каждого задания два пути:
  отнести в категорию или «Отклонить». Отдельный пункт меню «Без категории»
  уходит.
- «Скрыть тихо» остаётся для «красных» тем.
- «Удалить навсегда» — см. вопрос 1.

### 3.3. Паспорт и компания

- **Приложение:** первый вопрос анкеты специалиста — «Кто вы: Частный
  мастер / Компания или бригада». От ответа зависит проверка: частному
  мастеру — «Подтвердить личность» (паспорт), компании — «Подтвердить
  компанию» (название, Instagram, WhatsApp; паспорт — по желанию, ниже).
  Логотип не просим.
- **Админка, паспорт:** фото на весь экран с увеличением, готовые причины
  отказа: «Это не паспорт», «Не читается», «Не видно разворот с фото»,
  «Другое…». Отдельная кнопка **«Это компания → сделать компанией»**:
  тип аккаунта меняется, заявка на паспорт закрывается, человеку приходит
  уведомление «Заполните заявку на подтверждение компании».
- **Админка, карточка человека:** «Тип аккаунта: Частный мастер / Компания»
  — админ меняет сам (новая функция `admin_set_account_type`, журнал,
  уведомление человеку). Значок компании при смене снимается.

### 3.4. Уведомления (Web Push на iPhone)

iOS шлёт push сайтам, добавленным на экран «Домой» (iOS 16.4+), после
разрешения по нажатию кнопки. Нужно: service worker, ключи VAPID на
сервере, таблица подписок, отправка из `xtrud-api` при событиях.

Экран **«Уведомления»** в «Ещё»: переключатель по каждому событию —
новая жалоба, паспорт, компания, Instagram, «Большой опыт», звонок на
восстановление, задание на проверке, новое задание опубликовано, новый
специалист. По умолчанию включены очереди, выключены «новое задание» и
«новый специалист» (их много). Кнопка «Проверить» шлёт пробное
уведомление. У управляющего — только события, доступные его роли.

### 3.5. Ошибки

Чинятся по ходу и списком в отчёте: 30 системных окон → шторки;
повторяющиеся иконки; боковая шторка на телефоне. Плюс прогон каждого
раздела на ширине iPhone в обеих темах и проверка журнала ошибок клиента
и логов `xtrud-api` на ответы 4xx/5xx от админки. Ошибки, которые видел
владелец, — по его списку (вопрос 5).

## 5. Вопросы владельцу

1. **«Удалить навсегда»** нужно, или достаточно «Отклонить» (задание
   уходит из ленты, хранится в «Отклонённых», можно вернуть)? Предлагаю
   только «Отклонить»: удаление необратимо и стирает след для жалоб.
2. **«Компания или бригада»** — одним вариантом или тремя (Частный мастер /
   Бригада / Компания)? Предлагаю два варианта: проще выбрать, проверка
   у бригады и компании одна.
3. **Паспорт частного мастера** — обязателен (без него нельзя откликаться)
   или только настойчиво предлагается в анкете? Предлагаю второе: сейчас
   специалистов мало, барьер отпугнёт.
4. **Уведомления** — список событий в §3.4 подходит? Что добавить или убрать?
5. **Ошибки** — какие вы видели? Пришлите скриншоты или опишите, чиню их
   первыми.
6. **Стиль** — смотрим два направления на снимках (этап 0) и выбираете,
   или сразу делать в одном (тогда — тёмная «как iOS»)?

## 6. Ответы владельца и что сделано (2026-10-29)

Ответы (№368): (1) только «Отклонить» с возможностью вернуть, без удаления;
(2) два типа — «Частный мастер» и «Компания», бригада = компания; (3) паспорт
не обязателен, подтверждённый — значок у имени, смена имени снимает значок
(триггер `users_revoke_verification_on_name_change` уже был — FACT);
(4) уведомления — на усмотрение; (5) ошибка «Без категории» — висят
отклонённые/отменённые задания и счётчик; (6) один стиль сразу, светлый.
Дополнительно: №369 — «Большой опыт»: текст целиком, кнопки не огромные;
№370 — «Скрыть» заявку и список скрытых.

**База.** `0255_admin_mobile.sql` (ревью xtrud-security, применена
2026-10-29, копия `/opt/xtrud/backups/pre-0255-*.dump`): «Без категории» —
только открытые и не скрытые тихо; `admin_list_orders('rejected')`;
`admin_set_account_type`; Web Push (подписки, настройки по видам, триггеры
событий → `pg_notify('xtrud_admin_events')`, жалобы — через
`report_push_log` с его ограничениями); `deferred_at` у «Большого опыта».
`0256_admin_user_card_master.sql` — блок «специалист» в карточке человека.

**Сервер.** `server/src/push/webpush.ts` — LISTEN, рассылка через web-push
(VAPID; ключи — только в `/opt/xtrud/xtrud-api.env`), белый список хостов
push-сервисов, пробное не чаще раза в 30 с. `GET /v2/admin-push/key`.

**Админка.** Каркас с 4 вкладками (`components/Shell.tsx`), шторки вместо
`window.prompt/confirm` (`components/Sheet.tsx`, `feedback.tsx`: причины
чипами), светлая система (`styles/tokens.css`, `app.css`), PWA (`index.html`,
`public/manifest.webmanifest`, `public/sw.js`, иконки), число на иконке
(Badging API). Новые экраны: «Входящие», «Ещё», «Уведомления»; заново —
«Задания» (Проверка · В ленте · Отклонены · Скрытые + поиск по всем),
«Паспорта» (фото на весь экран, причины, «Это компания»), «Большой опыт»,
«Компании», Instagram, «Восстановление», «Жалобы», карточка задания и
человека (тип аккаунта). Старые адреса ведут в новые.

**Приложение.** Группа «Проверка» после «Анкеты»: «Кто вы» → паспорт
(частный) или компания + паспорт по желанию; значок у имени в шапке своего
профиля; подсказка на экране паспорта для компании.

**Не проверено (UNKNOWN):** доставка Web Push на iPhone владельца (нужно
добавить админку на экран «Домой» и включить в «Ещё → Уведомления»), вид в
standalone-режиме на устройстве, число на иконке.
