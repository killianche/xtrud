# Быстрый выбор подкатегории при создании задания (№241, 2026-10-05)

Запрос владельца: «посмотри, как у YouDo, Авито, Профи устроен быстрый поиск
подкатегории, чтобы человеку не приходилось кликать категорию, потом
подкатегорию; если у них удобнее — переделать».

## 1. Что у нас было

- Шаг «Какая категория?»: поле поиска и список из 12 разделов. Тап по разделу
  открывает его подкатегории, тап по подкатегории ведёт дальше. Два касания
  плюс поиск глазами.
- Поиск на этом шаге сравнивал только **названия** (`searchCategories` в
  `category-picker.ts`). FACT: «розетка», «течёт кран», «перевезти диван»
  ничего не находили, хотя на сервере есть умный поиск `search_categories`
  (синонимы, услуги, опечатки) и его копия во встроенном каталоге (382 слова).
  Им уже пользуются «Специалисты» и фильтр «Найти задание», но не
  конструктор.
- FACT (живая база): `search_categories('поменять розетку')` → Электрика,
  «перевезти диван» → Грузоперевозки, «настроить роутер» → Компьютерная
  помощь, «покрасить стены» → Штукатурка и покраска.

## 2. Референсы

| Сервис | Как начинается заказ | Что берём |
|---|---|---|
| Профи.ру | FACT (описание в App Store и RuStore): «вбить нужного специалиста в графу „услуга или специалист“», дальше — вопросы по услуге. Поиск первым, каталог не обязателен | Поле поиска — главный путь; подсказка по словам человека ведёт сразу к услуге |
| Авито | FACT (руководства продавцов): поиск подсказывает категорию по введённому слову; путь каталогом глубокий («Услуги → Строительство и ремонт → Электромонтаж») | Подсказка категории по слову, а не только по названию |
| YouDo | UNKNOWN: сайт закрыт для автоматической проверки; в App Store — 16 категорий и «создание задания занимает менее минуты» | — |
| TaskRabbit | FACT (главная): плитки категорий и «Popular Projects» — сразу конкретные задачи | Каталог как запасной путь для тех, кто листает |
| iOS 26 (Настройки, App Store) | Поиск сверху списка, результаты заменяют список по мере ввода | Тот же механизм: поле над списком, результаты на месте списка |

Вывод: у лидеров главный путь — **написать своими словами и выбрать
подсказку одним касанием**, каталог — запасной. У нас каталог был главным, а
поиск — слабым.

## 3. Варианты

- **A. Только починить поиск в конструкторе** (умный поиск вместо сравнения
  названий). Дёшево, но поле выглядит как «поиск по названию»: подсказка
  «электрик или уборка» не говорит, что можно написать задачу.
- **B (выбран). A + поле как вход «что нужно сделать»**: подсказка
  «Например, поменять розетку»; результаты — подкатегории, под каждой
  совпавшая услуга («Замена розетки / выключателя») или раздел; одно касание —
  следующий шаг. Каталог разделов остаётся под полем для тех, кто листает.
- **C. Угадывать категорию автоматически без вопроса** (как бы «по описанию»).
  Отвергнут: ошибка определения отправит задание не тем специалистам
  (уведомления идут по подкатегории), а человек этого не увидит.

Поле не открывает клавиатуру само: клавиатура закрыла бы список разделов
тем, кто пришёл листать; касание по полю — одно действие.

## 4. Реализация

- `src/features/categories/use-category-matches.ts` — общий подбор
  подкатегорий: сначала мгновенные совпадения по названию, затем умный поиск
  (сервер, без сети — встроенный каталог). Используют `CategoryMatches`
  («Специалисты», «Найти задание») и конструктор.
- `CategoryPickerTwoStep` — результаты поиска из этого подбора.
- `orders/new.tsx` — подсказка поля «Например, поменять розетку».
