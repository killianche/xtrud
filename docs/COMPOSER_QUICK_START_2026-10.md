# Создание задания: начать со слов, а не с каталога (№242, 2026-10-05)

Запрос владельца: «сделать лучшее решение, максимально короткое, быстрое и
качественное, как на YouDo или Авито… чтобы мы могли откатиться… с точной
продумкой количества нажатий, только то, что необходимо». Уточнение: «у них
вообще не показываются категории, только поиск — человек начинает вводить, и
только тогда появляются категории».

Продолжение №241 (`CATEGORY_QUICK_PICK_2026-10.md`): там умный подбор встал в
поле поиска над каталогом. Здесь меняется сам первый экран.

## 1. Разбор того, что есть (сборка 134)

Первый экран «Какая категория?»: поле поиска, под ним 12 разделов. Путь до
готовой категории и названия:

| Действие | Экран |
|---|---|
| 1. Касание раздела | «Какая категория?» |
| 2. Касание подкатегории | раздел |
| 3. Ввод названия, «Далее» | «Что нужно сделать?» |

Три касания и три экрана, и человек дважды формулирует одно и то же: сначала
ищет глазами категорию, потом пишет задачу словами. Список разделов —
главный элемент экрана, хотя главный путь у лидеров — слова.

## 2. Референсы

- **Профи.ру** — FACT (описание в App Store/RuStore): заказ начинается с поля
  «услуга или специалист», дальше вопросы по услуге.
- **Авито** — FACT (руководства продавцов): поиск подсказывает категорию по
  введённому слову. UNKNOWN: точный вид их экрана подачи на 2026-10.
- **YouDo** — UNKNOWN: сайт закрыт для автоматической проверки; со слов
  владельца — первый экран только поле, категории появляются при вводе.
- **iOS 26** — «Карты» и поиск в «Настройках»: на старте только поле с
  клавиатурой, подсказки появляются по мере ввода списком под полем, касание
  подсказки — сразу результат, без «Готово».

Что берём: первый экран — одно поле и клавиатура; категории — только
подсказками; текст из поля — сразу название задания (второй раз писать не
нужно); каталог — запасной путь из подсказок.

## 3. Шаг назад: варианты

**A. Оставить каталог, усилить поиск** (сделано в №241). Каталог остаётся
главным элементом — то, что владелец назвал «у нас наоборот».

**B (выбран). Первый экран — «Что нужно сделать?»:**

1. Крупный заголовок, одно поле (крупный шрифт, как название задания;
   растёт по тексту — длинное название не уезжает вбок), клавиатура
   открывается, как только экран доехал. Return закрывает клавиатуру, перенос
   строки в названии не нужен. Подсказка — только в самом поле: «Например,
   поменять розетку» (отдельная строка под полем говорила бы то же самое —
   design-quality §1.1). Каталога нет; под полем — тихая ссылка «Выбрать из
   списка категорий» для тех, кто не знает, как назвать задачу (иначе для
   них экран — тупик).
2. С двух букв под полем появляется группа «Подходящие категории» (тот же
   заголовок группы, что «Город»/«Район» в шторке места): до 5 подходящих
   подкатегорий (иконка, название, ниже — совпавшая услуга или раздел).
   Последняя строка — «Другая категория» → каталог (прежний экран разделов).
3. Касание подсказки: категория выбрана, написанное становится названием
   (первая буква — заглавная), переход на «Подробности». Клавиатура
   закрывается переходом.
4. «Подробности»: название уже заполнено и редактируется, описание и фото по
   желанию, «Далее».
5. Ничего не нашлось: «Не нашли подходящую категорию» и строка «Выбрать из
   списка» → каталог. Написанное сохраняется и станет названием.

Путь до готовой категории и названия:

| Действие | Экран |
|---|---|
| Ввод «поменять розетку» | «Что нужно сделать?» |
| 1. Касание «Электрика» | там же |
| 2. «Далее» (или добавить подробности/фото) | «Подробности» |

Два касания вместо трёх, на один экран меньше, а главное — не нужно искать
глазами: категория приходит из слов.

**C. Определять категорию автоматически, без подсказки.** Отвергнут:
ошибка тихо отправит задание не тем специалистам (уведомления идут по
подкатегории). Одно касание подтверждения дешевле ошибки.

## 4. Детали

- **Когда первый экран прежний (каталог):** правка категории с экрана
  проверки (`from=review`), категория устарела (`stale=1`), правка уже
  опубликованного задания — там человек меняет именно категорию, а название
  уже есть.
- **Вход с текстом** (`?draft=`) — текст сразу в поле, подсказки уже видны.
- **Скорость:** название подкатегории совпадает мгновенно (без сети); умный
  поиск — с задержкой 250 мс после последней буквы (`useDebouncedValue` в
  `useCategoryMatches`), а не запросом на каждую букву; без сети —
  встроенный каталог. Пока ищется следующая буква, прежние подсказки стоят на
  месте (`keepPreviousData`), новые дописываются ниже совпадений по названию —
  строки не прыгают под пальцем.
- **Фразы своими словами.** FACT (живая база): серверный поиск ищет фразу
  целиком — «нужно поменять розетку на кухне», «собрать шкаф и повесить полку
  в детской» не находил ничего. Добавлен пословный подбор по встроенному
  каталогу (`searchCatalogByWords`): каждое значимое слово по основе
  («розетку» → «розет»), общие глаголы («поменять», «починить») и место («на
  кухне») весят мало. Результат: розетка → Электрика, шкаф и полка → Мастер на
  час и Мебель и сборка, «течёт кран в ванной» → Сантехника, «поклеить обои в
  спальне» → Обои. Без сети, мгновенно; тесты — `catalog-word-search.test.ts`.
- **Состояния:** до двух букв — только ссылка в каталог; ищем — скелетон из
  трёх строк, только если показать ещё нечего; не нашли — текст и «Выбрать из
  списка»; каталог не загрузился — «Не удалось загрузить категории» и
  «Повторить».
- **Отклик:** выбор строки — лёгкая вибрация выбора (уже встроена в
  `InsetRow`); VoiceOver объявляет, сколько подсказок появилось.
- **Каталог из подсказок** (`/orders/new/catalog`): прежний экран разделов →
  подразделы; выбор там тоже берёт написанное как название.
- **Accessibility:** поле с меткой «Что нужно сделать», строки подсказок —
  кнопки с названием и подписью; Dynamic Type — строки растут по тексту.
- **«Подробности»:** второй экран при новом пути называется «Подробности»
  (вопрос «Что нужно сделать?» уже задан), название заполнено и
  редактируется, клавиатура сама не открывается.
- **Название:** первая буква заглавная, остальное как написал человек
  (`titleFromQuery`).
- **QA и приёмка** (2026-10-05): исправлены пустота при одной букве в
  «Специалистах» и фильтре (там подбор, как раньше, с первой буквы) и пустой
  экран, пока не пришёл флаг (сразу новый путь, «catalog» — только явный
  откат).
- **Проверено дизайн-ролью до реализации** (2026-10-05): приняты растущее
  поле, Return, задержка поиска, состояние ошибки, ссылка в каталог при
  пустом поле, «Подробности», заглавная буква, неподвижные строки, объявление
  VoiceOver; отклонено как избыточное — отдельная подпись под полем.

## 5. Откат

Флаг `composer_start` в `app_settings` (`"quick"` — новый путь, по умолчанию;
`"catalog"` — прежний первый экран). Переключатель — в веб-админке,
«Настройки» → «Создание задания»; новая сборка для отката не нужна.
Миграция `0228_composer_start_flag.sql`, откат кода — `git revert`.
