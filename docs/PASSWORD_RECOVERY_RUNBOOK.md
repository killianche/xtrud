# Восстановление доступа к аккаунту — инструкция для владельца

> DECISION владельца 2026-09-03: восстановление телефонных аккаунтов —
> **вручную через поддержку**. SMS-код и «почта для восстановления в профиле»
> рассмотрены и отложены.

## Почему это вообще нужно делать руками

Регистрация с 2026-09-01 — только номер телефона и пароль. Адрес для
авторизации строится синтетически: `<цифры номера>@phone.xtrud.pro`. Такого
почтового домена не существует, поэтому стандартное письмо со ссылкой на
сброс пароля уходит в никуда.

Проверить, кого это касается:

```sql
SELECT count(*) FILTER (WHERE email LIKE '%@phone.xtrud.pro') AS bez_pochty,
       count(*) FILTER (WHERE email NOT LIKE '%@phone.xtrud.pro') AS s_pochtoy
FROM auth.users;
```

На 2026-09-03: 8 аккаунтов без почты из 63.

Аккаунты, зарегистрированные раньше по почте, восстанавливаются сами —
экран «Забыли пароль» им работает.

## Что видит человек

На экране «Забыли пароль» есть врезка «Регистрировались по номеру телефона?»
с кнопкой «Написать в поддержку» → `https://wa.me/79289204029` (WhatsApp,
DECISION владельца 2026-09-11; прежний `t.me/xtrud_support` не существовал —
тестировщик получал от Telegram «такого пользователя нет»). Это единственный
честный путь, пока восстановление ручное.

С 2026-09-11 в админке есть и смена номера входа (0190) — для тех, кто
потерял симкарту: карточка человека → «Номер входа». Прежние входы
прекращаются, значок проверенного снимается.

## Порядок действий

1. **Убедиться, что пишет владелец аккаунта.** Проверяемый минимум: номер
   телефона и хотя бы один факт, который знает только он — заголовок его
   задания, город, дата создания аккаунта. Совпал только номер — этого мало:
   номер могли подсмотреть в отклике.

2. **Найти аккаунт.** На Beget:

   ```bash
   ssh xtrud-beget
   docker exec -it supabase-db psql -U postgres -d postgres
   ```

   ```sql
   SELECT id, email, created_at, last_sign_in_at
   FROM auth.users
   WHERE email = '<цифры номера>@phone.xtrud.pro';
   ```

   Номер — только цифры, без `+` и пробелов: `79991234567`.

3. **Задать новый пароль.** Безопаснее всего — через Supabase Studio
   (`Authentication → Users → … → Reset password`), там пароль хешируется
   штатным механизмом.

   Если делать в SQL, хеш обязан быть bcrypt — иначе вход молча перестанет
   работать:

   ```sql
   UPDATE auth.users
   SET encrypted_password = crypt('<новый пароль>', gen_salt('bf')),
       updated_at = now()
   WHERE email = '<цифры>@phone.xtrud.pro';
   ```

4. **Передать пароль человеку** и попросить сменить его. Не отправлять пароль
   в общий чат.

5. **Записать факт** в TASKS.md: кому и когда меняли. Это защита от «мне не
   меняли, у меня украли аккаунт».

## Чего не делать

- Не менять `email` у аккаунта, чтобы «прикрутить почту» — сломается
  `resolve_login_email`, и человек не войдёт по номеру.
- Не удалять и не пересоздавать аккаунт: к нему привязаны задания, отклики и
  отзывы, они потеряются.
- Не выдавать новый пароль по номеру, который прислали в переписке, без
  второй проверки.

## Когда это перестанет масштабироваться

Ручной способ рассчитан на десятки пользователей. Признак, что пора делать
автоматику (SMS-код или почта в профиле): больше 2–3 обращений в неделю либо
публичный запуск. Оба варианта описаны в блокере в `TASKS.md`.
