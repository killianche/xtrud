# Приоритет услуг xtrud

Каноническая доказательная матрица для каталога и порядка запуска. Она отвечает
на три разных вопроса, которые нельзя смешивать:

1. что уже доступно в текущем приложении;
2. какие группы покрывает целевая таксономия;
3. для каких групп есть основания запускать их раньше других.

Дата проверки внешних источников: **2026-08-26**.

## Как читать статусы

- **FACT** — подтверждено кодом, снимком каталога или указанным первичным
  источником;
- **DECISION** — обратимое продуктовое решение xtrud, а не рыночная статистика;
- **HISTORICAL SIGNAL** — опубликованный, но не текущий и/или не локальный
  сигнал;
- **UNKNOWN** — данных недостаточно. UNKNOWN нельзя переименовывать в
  «непопулярное»;
- **RESTRICTED** — требуется юридическая, документальная или модерационная
  проверка до включения.

Размер каталога конкурента, место пункта в меню и число исполнителей не
доказывают спрос клиентов. До появления достаточной локальной выборки UI может
писать только «Рекомендуем», но не «Популярное» или «В тренде».

## FACT — что уже есть

- CURRENT mobile scope задан в `src/lib/product-scope.ts`: `construction` и
  `home-services`.
- Generated offline snapshot содержит 37 L2, 285 L3 и 288 terms; фактически все
  37 L2 относятся к `construction`. Это release-снимок текущего backend, а не
  полный target-каталог.
- Канонический seed уже содержит семь L2 ветки `home-services`: клининг,
  стирка/чистка, вывоз, сад/участок, ТВ/интернет, борьба с вредителями и бытовая
  техника. Их отсутствие в текущем bundle — обнаруженный backend/catalog gap,
  который нельзя скрывать ручным редактированием generated JSON.
- Полный TARGET на 10 пользовательских L1 подготовлен в feature-off draft
  `0120`. Он не входит в runnable migrations и не активирован. Search aliases
  TARGET-веток намеренно не вставляются: текущий public synonym RPC не
  фильтрует выключенные targets и мог бы раскрыть их старому клиенту.
- `is_featured` у сантехники и ремонта/отделки — ручная курация, а не
  измеренная популярность.
- Версионированного полного SQL-источника production-аналитики популярности в
  репозитории пока нет. Реальный локальный рейтинг Магаса/Назрани — `UNKNOWN`.

## DECISION — порядок запуска

| Приоритет | Группы | Основание и граница |
|---|---|---|
| **Core / сейчас** | сантехника и отопление; электрика; ремонт и отделка; мастер на час; окна; двери и замки; обои и малярные работы; полы; плитка; мебель; кровля и фасад | Уже входят в CURRENT xtrud и одновременно присутствуют в текущем каталоге Яндекса. Это приоритет запуска, не утверждение о локальном рейтинге спроса. |
| **Core gap / следующий безопасный срез** | генеральная и регулярная уборка; химчистка мебели и ковров; дезинсекция; глажка; бытовой вывоз мусора; подключение бытовой техники | Уже предусмотрены `home-services` или подтверждены current discovery placement. Сначала требуется reconcile backend с canonical seed и новый generated snapshot; generated JSON вручную не менять. |
| **Market-priority candidate** | ремонт/установка техники; перевозки и курьеры; авто; образование; затем IT, виртуальный помощник и beauty | Покрываются обоими рынками и/или историческими сигналами. Включать пилотами после локальной проверки спроса и предложения. |
| **Experiment / long tail** | творчество и хобби; артисты; животные; event/photo/audio; дизайн; business/legal; редкие строительные специализации | Локальный спрос не подтверждён. `long tail` означает UNKNOWN, а не «непопулярно». |
| **Restricted / verify** | медицина и инъекционные процедуры; газ; электрика с допуском; аварийное вскрытие; охрана; уход за детьми/пожилыми; регулируемые юридические статусы | Нужны server-side verification/moderation и отдельный legal contract. Одного скрытия в UI недостаточно. |
| **Вне продукта** | товары; аренда без услуги; вакансии и постоянная занятость; тендеры и долгие B2B-проекты; незаконные задания | Не соответствует модели короткого задания и отклика xtrud. |

## Как получить честный локальный рейтинг

Для каждой L2 и региона нужны rolling 7/30-day агрегаты без PII:

- уникальные пользователи поиска;
- доля запросов без результата;
- явный выбор категории и способ выбора;
- опубликованные задания;
- задания хотя бы с одним откликом;
- медианное время до первого отклика;
- отмены/модерационные отклонения.

Yandex Wordstat может дать внешний региональный baseline по частотности и
динамике, но он требует отдельного доступа к API. Источник:
[официальное описание API Wordstat](https://yandex.ru/company/news/01-09-06-2025).

До утверждения окна и минимальной выборки:

- нельзя автоматически присваивать статус «популярное»;
- нельзя называть категорию «непопулярной»;
- zero-result запросы используются для расширения словаря, но не для скрытого
  назначения категории;
- rollout остаётся флаговым: `task_creation_enabled` → `catalog_enabled` →
  `matching_enabled`, с обратимым отключением без удаления данных.

## Acceptance criteria

- обе CURRENT L1 присутствуют в authoritative backend и release-bound bundle;
- owner-примеры покрыты golden corpus: «поклеить обои», «поклеить плёнку на
  окна», «убрать двор», «тракторист», «юрист»;
- exact known intent предлагает вариант, ambiguous показывает не более трёх
  категорий, unknown сохраняет текст и ведёт в ручной выбор;
- категория никогда не назначается без явного тапа;
- disabled/internal/restricted categories не протекают через search RPC,
  direct URL или старый клиент;
- внешний market-priority и локальная popularity аналитика названы разными
  сущностями;
- ни одна TARGET-ветка не активируется до restore/security/search compatibility
  gates и отдельной forward-only activation migration.
