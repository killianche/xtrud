# Текущая classifieds-модель xtrud

## TL;DR

**Имя для запроса:** «простой flow», «доска объявлений», «как работает заказ
сейчас».

Клиент создаёт заказ, мастер отправляет один отклик с сообщением и ценой,
клиент сам звонит или пишет мастеру в WhatsApp. Номер клиента скрыт. В xtrud
нет in-app чата, выбора исполнителя, lifecycle сделки, спора и платформенных
платежей.

Этот документ описывает **CURRENT**. Целевое расширение на любые разрешённые
разовые услуги описано отдельно в
[`UNIVERSAL_TASK_BOARD.md`](UNIVERSAL_TASK_BOARD.md); оно не считается
включённым до feature rollout.

## 1. Happy path клиента

1. Клиент находит мастера в каталоге либо создаёт заказ.
2. В заказе указывает категорию, заголовок, детали, до 5 фото, место, срок,
   бюджет и отображаемое имя.
2a. При создании клиент выбирает способ связи: отклики в приложении (номер
    скрыт) или звонок/WhatsApp напрямую (номер в задании, откликов нет —
    DECISION владельца 2026-09-07, `orders.contact_mode`).
3. Мастера видят открытый заказ и откликаются одним сообщением с ценой и
   опциональным сроком.
4. Клиент открывает свои отклики, сравнивает мастеров и сам инициирует звонок
   или WhatsApp.
5. После фактической работы клиент может оставить отзыв мастеру.

Нажатие контакта не означает, что мастер «выбран» внутри продукта. xtrud не
знает и не меняет состояние реальной договорённости сторон.

## 2. Happy path мастера

1. Пользователь на странице аккаунта нажимает «Стать специалистом» и в хабе
   «Я специалист» выбирает категории, пишет о себе, добавляет фото работ и
   контакты; в каталоге он виден с первой категории (0169).
2. Мастер видит открытые заказы по своим категориям и доступным фильтрам.
3. На чужой открытый заказ мастер отправляет один отклик: текст, цену и
   опциональный срок исполнения.
4. Контакта клиента мастер не получает. Если клиент заинтересован, клиент сам
   связывается с мастером.

## 3. Состояния и границы

Пользовательский CURRENT использует:

- `open` — заказ опубликован и принимает отклики;
- `cancelled` — клиент отменил заказ;
- `expired` — срок публикации истёк;
- локальный черновик формы до публикации.

В историческом enum/RPC могут оставаться lifecycle-значения и функции. Они не
являются разрешением возвращать UI «выбран / в работе / завершён / спор».
Перед изменением backend сначала нужен live read-only snapshot, потому что
migration chain не доказан как полный production snapshot.

## 4. Чего нет

- in-app чата и таблицы пользовательских сообщений;
- таба «Чаты» и notification flow новых сообщений;
- выбора победившего отклика;
- статуса сотрудничества или подтверждения выполнения;
- dispute flow;
- рейтинга клиента;
- escrow, комиссии или приёма оплаты площадкой;
- фамилии в пользовательском flow.

Жалоба и модерация существуют отдельно: они управляют допустимостью контента и
пользователей, но не являются спором по сделке.

**Способ проверки, 2026-08-23:** исполняемый код и Git migrations в указанных
путях. Live production schema этой записью не подтверждена.

## 6. Когда применять / не применять

**Применять:** при любом изменении заказов, откликов, контакта, отзывов или
модерации — чтобы не вернуть старый marketplace lifecycle случайно.

**Не применять как полную спецификацию universal scope:** для category flags,
unknown-category, `work_mode`, auth-return, matching и block contract читать
[`UNIVERSAL_TASK_BOARD.md`](UNIVERSAL_TASK_BOARD.md).
