# Управляющие и действия в приложении (№286, 2026-10-07)

Запрос владельца:

> «Мне пришло уведомление: в админке нужно поставить категорию, а с телефона
> я не могу. Давай некоторые аккаунты сделаем управляющими: внутри админки
> их можно назначать. Управляющий получает задания без категории, назначает
> категории, блокирует и разблокирует — часть функций админа, не всё. И
> админ, и управляющий выполняют базовые команды прямо в приложении.»

## 1. Что есть сейчас (FACT)

- Роль одна: `users.is_admin`. Проверка — `is_admin_session()` (админ, не
  demo, активен), её вызывают все 54 функции `admin_*`.
- Веб-админка пускает только админа. Назначить админа можно только запросом
  в базе.
- В приложении у админа уже есть:
  - «Скрыть задание (админ)» в меню задания;
  - «Скрыть тихо» на карточке;
  - «Заблокировать аккаунт (админ)» в меню профиля мастера.
- Назначить категорию из приложения нельзя. Уведомление «Новое задание без
  категории» никуда не ведёт.

## 2. Роли

| | Админ | Управляющий |
|---|---|---|
| Задания без категории: список, назначить, принять подсказку нейросети, «Спросить нейросеть» | ✓ | ✓ |
| Создать подкатегорию из задания (через нейросеть или вручную) | ✓ | ✓ |
| Скрыть или вернуть задание, «красный флаг» | ✓ | ✓ |
| Жалобы: смотреть, решать | ✓ | ✓ |
| Заблокировать или разблокировать пользователя, предупредить | ✓ | ✓ |
| Уведомления о заданиях без категории и жалобах | ✓ | ✓ |
| Каталог: правка, слияние, порядок, разделы | ✓ | — |
| Паспорта и Instagram (персональные данные), восстановление доступа, смена телефона или пароля | ✓ | — |
| Рассылки, баннеры, настройки и флаги, лимиты, метрики | ✓ | — |
| Команда: назначать и снимать управляющих | ✓ | — |
| Выдать или снять права администратора | только вручную в базе | — |

**Почему такая граница.** Управляющий делает ежедневную работу с заданиями
и людьми. Всё, что меняет продукт для всех (каталог, флаги, рассылки) или
открывает персональные данные (паспорта, телефоны), остаётся у админа.
Блокировка доступна управляющему, но идёт в журнал с его именем, и админ
может снять её.

## 3. Данные и проверки

- `users.staff_role`: `null | 'manager'`; `is_admin` остаётся как есть.
- `is_staff_session()` = админ или управляющий (не demo, активен).
- Функции, открытые управляющему, переходят с `is_admin_session()` на
  `is_staff_session()`. Остальные не меняются, поэтому по умолчанию закрыто
  всё, что явно не открыто.
- Новая функция `admin_set_staff_role(user_id, role, reason)` — только для
  админа и только для роли управляющего. Себя поменять нельзя.
- Права администратора интерфейс не меняет: вход в админку — только пароль,
  и утёкший пароль не должен позволять назначить себе запасных админов и
  снять владельца. Админа по-прежнему назначает владелец базы через psql
  (ревью `xtrud-security` 2026-10-07, I1).
- `admin_log_action` больше нельзя вызвать напрямую: в журнал пишут только
  функции `admin_*` (ревью, M1).
- Роль в приложении и веб-админке подтверждает база (`my_staff_role()`):
  demo и приостановленные сотрудники кнопок не видят.
- Журнал `admin_actions` уже пишет `admin_id`: видно, кто из управляющих что
  сделал.
- Уведомления «без категории» и о жалобах получают админы и управляющие.

## 4. Веб-админка

- Вход открыт и управляющему. Меню показывает только разрешённые разделы,
  прямой адрес закрытого раздела показывает «Нет доступа». Защита всё равно
  в базе, меню — для удобства.
- Новый раздел «Команда» (только админ):
  - список админов и управляющих;
  - «Добавить управляющего» — поиск человека по телефону или имени;
  - «Убрать» — у управляющего; у админа кнопок нет.

## 5. Приложение (админ и управляющий)

- **Профиль → «Управление».** Счётчики: без категории, жалобы, скрытые.
  Отсюда открывается список «Без категории».
- **«Без категории» в приложении.** Для каждого задания:
  - подсказка нейросети;
  - «Принять» в одно касание;
  - «Выбрать категорию» — штатная шторка каталога;
  - «Открыть задание».
- **Меню «⋯» задания** для админа и управляющего:
  - «Назначить категорию»;
  - «Скрыть задание» / «Вернуть»;
  - «Заблокировать клиента».

  Всё через общее меню действий (`src/lib/action-menu.ts`).
- **Профиль человека.** «Заблокировать / Разблокировать» с причиной.
- **Касание уведомления** «Новое задание без категории» открывает это
  задание в приложении.

## 6. Порядок работ

1. Миграция 0239: роль, `is_staff_session`, перевод разрешённых функций,
   `admin_set_staff_role`, получатели уведомлений. Проверка роли
   безопасности обязательна: это расширение прав.
2. Сервер: allowlist, `/v2/admin/ai/assist` для управляющего.
3. Веб-админка: меню по роли, «Команда».
4. Приложение: «Управление», «Без категории», пункты меню, переход по
   уведомлению. Сборка iOS и Android.

## 7. Итог реализации (2026-10-07)

- Миграция 0239 и откат; репетиция на живой базе внутри транзакции с
  откатом: роль, права, журнал, откат — проверены.
- Приложение: «Профиль → Управление» (админ — 4 раздела, управляющий — 2),

  без категории».

  разделе, «Команда»; управляющему не показываются телефон, адрес входа,

  - push о новых жалобах (сейчас никому не приходит);
  - `users.contact_phone` читает любой вошедший — отдельная задача;
