# Конструктор задания — как у Apple и больших сервисов

**Имя для запроса:** «форма заявки», «создание задания», «конструктор», «TaskRabbit»,
«что изучили про формы».

> DECISION владельца 2026-09-06 (вечер): «изучи, как Apple и большие компании
> (TaskRabbit и подобные) детально и технически делают регистрацию и форму
> заявки; потом с нуля сделай нам новую форму создания заданий. Не
> ориентируйся на старый вариант. Всё в духе и стиле Apple iOS Liquid Glass».

## 1. Что узнали (FACT — источники ниже)

### Apple, Human Interface Guidelines

- **Entering data.** Не проси вводить то, что можно узнать самому; подставляй
  разумные значения по умолчанию; предлагай выбор вместо ввода; клавиатура —
  под тип данных; подсказка объясняет, что писать; проверяй значение сразу,
  как обнаружил проблему; **кнопку «Далее» включай только когда обязательное
  заполнено**.
- **Text fields.** Однострочное поле — под объём ожидаемого текста; кнопка
  очистки справа (iOS); проверять e-mail — когда поле покинули, пароль — до
  перехода дальше; несколько полей — в столбик, одной ширины, с логичным
  порядком.
- **Новая система дизайна (WWDC25, «Get to know the new design system»).**
  Строки навигации и панели инструментов без своих фонов — иерархия через
  расположение и группировку; главное действие («Готово») стоит отдельно и
  выделено цветом; **кнопки Liquid Glass лежат на системном материале, а не
  прямо на содержимом**; выпуклая (prominent) кнопка получает оттенок;
  капсулы — форма кнопок и элементов управления; радиусы вложенных фигур
  считаются концентрично; шторки действий вырастают из самого действия;
  один scroll-edge-эффект на экран; типографика жирнее и выровнена влево в
  ключевых моментах (онбординг, предупреждения).
- **Liquid Glass (обзор технологии).** Стандартные элементы получают
  материал сами; цвет в элементах управления — сдержанно, чтобы содержимое
  оставалось читаемым; предсказуемое расположение действий и стандартные
  символы.

### TaskRabbit, Thumbtack, исследования форм

- **TaskRabbit (редизайн Big Human).** Клиент описывает задачу, ставит
  бюджет и выбирает дату; уточняющие вопросы — по желанию, и **ответы можно
  править в любой момент**; рекомендации исполнителей по бюджету и опыту;
  панель после заказа показывает статусы и следующий шаг.
- **Thumbtack.** Вопросы задаются **по одному на экран** дружелюбным тоном —
  форма воспринимается лёгкой и быстрой (прогрессивное раскрытие).
- **Многошаговые формы (сводки Designlab, Webeyez и др.).** Один вопрос/тема
  на шаг; индикатор прогресса снижает отказы; **автосохранение каждого шага**
  с продолжением с того же места; одноколоночная раскладка; клавиатура под
  тип поля.
- **Проверка ввода (NN/g, UXPin).** Проверять **после завершения поля**, а не
  на каждую букву; ошибка — рядом с полем, коротко; сводки ошибок на
  мобильных не работают.

## 2. Что из этого стало правилами xtrud

| Правило | Где в коде |
|---|---|
| Один вопрос на экран, каждый шаг — маршрут Stack: «назад» и свайп от края — один POP | `app/(details)/orders/new*.tsx`, `src/features/task-composer/steps.ts` |
| Порядок: что → подробности → где → когда → бюджет → контакты → проверка | `COMPOSER_STEPS` |
| «Далее» включается только когда обязательное заполнено; ошибки — после ухода из поля | `isStepValid`, `ComposerField` |
| Выбор вместо ввода: место, срок, тип цены — строками с галочкой | `ChoiceGroup`/`ChoiceRow` |
| Ничего не выбрано заранее там, где выбор влияет на отклики (срок, бюджет) | `EMPTY_COMPOSER_VALUES` |
| Не просить то, что знаем: телефон из аккаунта подставляется, но его можно заменить | `new/contacts.tsx` |
| Автосохранение: черновик пишется при каждом ответе, переживает вход и перезапуск | `useComposer` → `useOrderDraftStore` |
| Проверка перед публикацией: каждая строка ведёт на свой шаг («Готово» возвращает) | `new/review.tsx`, `useStepNavigation` |
| Главное действие — одна выпуклая капсула Liquid Glass в фирменном цвете внизу; второстепенное — текстом | `ComposerScreen` |
| Клавиатура поднимает кнопку, не закрывает её | `KeyboardAvoidingView` в `ComposerScreen` |
| Индикатор шагов — тонкие капсулы в строке навигации; VoiceOver читает «Шаг N из M» | `ComposerScreen` |
| Закрыть на первом шаге при непустом черновике — системный action sheet: сохранить/удалить | `new.tsx` |
| Категория подтверждается только тапом, сама не назначается | `task-intent-suggestions.ts` |
| Публикация: сверка категории и места с сервером → лимит → фото → insert → владелец результата | `use-publish-task.ts` |
| Редактирование — тем же конструктором с экрана проверки | `edit/[id].tsx`, `useComposerSession` |

## 3. Что не делаем (и почему)

- Календарь на месяц: полоса ближайших 30 дней покрывает реальные сроки, а
  выбор «через полгода» здесь не нужен (простота, design-quality §1.1).
- Обязательные контакты: номер по желанию — модель «контакты в отклике»
  сохраняется (DECISION 2026-09-01).
- Автоназначение категории по тексту: ошибка каталога дороже одного тапа.
