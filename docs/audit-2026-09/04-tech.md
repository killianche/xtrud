## 0. Коротко

**Оценка кода в целом: крепкая «четвёрка» для проекта такого размера.**
Строгая типизация (0 `any`, 0 `@ts-ignore`), правила доступа в базе (RLS на
всех таблицах с данными, у всех 86 `SECURITY DEFINER` задан `search_path`),
тонкий и понятный сервер (~2 100 строк), продуманные таймауты и повторы.
Слабые места — не в стиле кода, а в **эксплуатации** (никто не узнает о
падении, бэкапы лежат на том же диске, диск заполнен на 78 %), в **весе и
холодном старте** (треть JS-бандла — неиспользуемые иконки) и в **процессе**
(CI не запускается на push, цепочка миграций не отражает production).

Топ-5 технических рисков (подробно — §8):

1. **Нет внешнего мониторинга и алертов.** Инцидент 16.09 (9,5 ч простоя)
   может повториться так же незаметно: таймеров/проверок нет, кроме ночного
   бэкапа (FACT, §4.4).
2. **Бэкапы только на том же VDS, без PITR, восстановление не отрепетировано.**
   `archive_mode = off`; копии в `/opt/xtrud/backups` на том же диске
   (FACT, §4.3). Потеря VDS = потеря данных и файлов-зеркала.
3. **Диск production заполнен на 78 % (37 из 48 ГБ), из них 20,2 ГБ — кэш
   сборки Docker** (FACT, §4.5). Заполнение диска остановит PostgreSQL.
4. **Живая схема не воспроизводится из репозитория.** `supabase/migrations/`
   кончается на 0133, 54 из 116 живых функций определены только в
   `migration-drafts/`, 3 живые функции не имеют исходника вовсе, таблицы
   учёта применённых миграций нет (FACT, §6.4).
5. **Сбои в приложении не читаются.** Стеки `client_errors` без
   символизации: source maps не сохраняются, в отчёте нет номера сборки
   (FACT, §4.6). Следующий fatal-краш снова будет разбираться вручную.

Главный резерв скорости — не сервер (он быстрый: p50 10 мс, p95 63 мс,
FACT §3.6), а **клиент и сеть**: 33,6 % JS-бандла — `phosphor-react-native`
(3 027 модулей при 113 используемых иконках), ответы API не сжимаются
(14,2 КБ вместо 2,6 КБ), нет HTTP/2, на старте 12–15 отдельных запросов.

## 1. Архитектура

### 1.1. Слои и поток данных (FACT)

```
Экран app/**.tsx (expo-router, 78 экранов)
  └─ хук src/features/**/use-*.ts (react-query: 54 useQuery/useInfiniteQuery, 36 useMutation)
      └─ @/lib/supabase  → свой клиент src/lib/xtrud-client (1 222 строки вместе с sse/realtime-topic)
          ├─ /v2/rest/<таблица>  → Fastify-прокси (server/src/rest/routes.ts, allowlist 22 таблиц) → PostgREST v14.12 → PostgreSQL (RLS)
          ├─ /v2/rpc/<функция>   → Fastify-мост (server/src/rpc/routes.ts, allowlist 50 функций) → pg под SET LOCAL ROLE → функции SECURITY DEFINER
          ├─ /v2/auth/*          → свой вход (bcrypt, JWT HS256, refresh с ротацией)
          ├─ /v2/files/*         → Beget S3 (nginx-кэш 7 дн.), /render/* → xtrud-imgproxy
          └─ /v2/events (SSE)    ← LISTEN в xtrud-api ← pg_notify (0189)
PostgreSQL: pg_cron (8 задач), pg_net → /v2/internal/push → APNs / RuStore
```

- Сервер — Docker-контейнер `xtrud-api` (`restart: unless-stopped`,
  `mem_limit 512m`, healthcheck каждые 30 с), **не systemd-юнит**:
  `systemctl status xtrud-api` → «Unit xtrud-api.service could not be found»;
  `docker ps` → `xtrud-api … Up 6 days (healthy)` (FACT). Исходник на Beget
  (`/opt/xtrud/xtrud-api/src`) побайтно совпадает с `server/src` в HEAD
  (сравнение sha256 всех `.ts`, FACT).
- Живые контейнеры xtrud: `xtrud-api`, `xtrud-imgproxy`, `supabase-rest`
  (PostgREST), `supabase-db` (`supabase/postgres:17.6.1.136`). Порты БД и
  PostgREST наружу не опубликованы; публично слушают только 22/80/443 (FACT,
  `ss -ltn`). UFW выключен (`Status: inactive`) — защита держится на том, что
  сервисы привязаны к 127.0.0.1 или docker-сети.

### 2.3. Ключи react-query и инвалидации

Сильная сторона: большинство ключей — фабрики (`myOrdersKey`,
`orderDetailKey`, …), 116 вызовов `invalidateQueries`. Слабые места (FACT):

1. **Отклик не обновляет «Мои отклики».** `useSubmitResponse`
   (`src/features/orders/use-order-responses.ts:117-124`) инвалидирует
   `orderResponsesKey`, `myResponseKey`, `orderDetailKey`, лимит — но не
   `myResponsesKey(masterId)` и не `myRespondedOrderIdsKey`. Симметричный
   `useWithdrawResponse` (`use-withdraw-response.ts`) `myResponsesKey`
   инвалидирует. SSE-обработчик `refreshAll`
   (`use-realtime-notifications.ts:48-57`) `myResponsesKey` тоже не трогает.
   Итог: после отклика вкладка «Мои задания → Отклики» может показывать
   старый список до 30 с (`staleTime: 30_000`, `use-my-responses.ts:71`).
2. **Лента открытых заданий (`all-open-orders`) не инвалидируется ни одной
   мутацией заданий** (create/cancel/delete/lifecycle/reopen/update —
   проверено по всем 8 хукам мутаций). Для автора последствия малы (свои
   задания в ленте скрыты фильтром `neq client_id`), но ключ ещё и
   **сохраняется на диск на 24 ч** (`app/_layout.tsx:199-200`), поэтому после
   холодного старта первым кадром показывается снимок до суток давности.
   Это осознанное решение («мгновенно») — нужна лишь пометка «обновлено N
   мин назад» или `refetchOnMount: "always"` для этого ключа.
3. Смешение литералов и констант: лимит откликов инвалидируется литералом
   `["response-limit-today"]` (`use-order-responses.ts:124`) и константой
   `RESPONSE_LIMIT_QUERY_KEY` (`use-withdraw-response.ts`) — сейчас совпадают,
   но это ровно тот класс рассинхрона, что уже ломал бейджи. 10 мест
   используют литерал `["master-public", …]`, 5 — `["search-masters", …]`.
   Фабрика ключей в одном файле `src/lib/query-keys.ts` + правило Biome
   (запрет литеральных `queryKey`) — S.

### 3.2. Холодный старт — что происходит до первого экрана (FACT, `app/_layout.tsx`)

Хорошо: шрифт системный, splash скрывается сразу после маунта (`:248`);
`SafeAreaProvider initialMetrics` убирает пустой кадр; публичные списки
(`all-open-orders`, `search-masters`) восстанавливаются из AsyncStorage.

Сетевые запросы залогиненного человека при открытии «Главной» (по коду
`app/(tabs)/_layout.tsx` и `app/(tabs)/index.tsx`):

- `useUserRecord`, `useMyMasterCategories`, `touch_last_active`;
- 5 счётчиков `count: exact, head: true` (уведомления, события заданий,
  отзывы, отклики, лента) — отдельные запросы;
- SSE `/v2/events`;
- «Топ специалистов»: `master_profiles`, затем `cities` + `master_categories`
  (2 последовательных круга, `use-top-masters.ts:42,101,105`);
- **по RPC `record_master_view` на каждую карточку** специалиста в карусели
  (`app/(tabs)/index.tsx:418-421`) — N+1 на запись; в логах API это третий по
  частоте маршрут (186 вызовов за 6 дней, §3.6);
- лента/витрина открытых заданий.

Итого **~12–15 HTTP-запросов** до «успокоения» экрана. Сервер отвечает за
~10 мс, значит время съедает сеть: каждый круг = RTT, а nginx отдаёт
**HTTP/1.1** (FACT: `curl -w %{http_version}` → `1.1`) — iOS держит до 6
соединений на хост, остальные ждут. Решение: один RPC `get_app_badges`
(5 счётчиков одним вызовом), пакетная запись показов
(`record_master_views(uuid[])`), `http2` в `listen 443`.

### 3.3. Сжатие ответов (FACT)

`nginx.conf`: `gzip on`, но `gzip_types` и `gzip_proxied` закомментированы →
JSON не сжимается. Замер: `GET /v2/rest/categories_l2?select=*` с
`Accept-Encoding: gzip, br` вернул `Content-Length: 14252` без
`Content-Encoding`; тот же ответ в gzip — **2 590 байт (в 5,5 раза меньше)**.
На мобильной сети это заметно на каждом списке. Правка — 2 строки nginx
(`gzip_proxied any; gzip_types application/json;`), стоимость S, риск низкий.

### 3.4. Кэш react-query (FACT)

`staleTime 30 с`, `gcTime 5 мин` по умолчанию, 58 локальных `staleTime`,
`refetchOnWindowFocus: false` глобально (с включением у бейджей),
persist — 2 публичных ключа на 24 ч. Разумно. Замечание: `gcTime 5 мин` при
переключении вкладок дольше 5 мин выбрасывает кэш деталей — для справочников
(категории, города) можно `staleTime: Infinity` + версия каталога.

## 10. UNKNOWN — что не проверено и как проверить

| Что | Как проверить |
|---|---|
| Реальное время холодного старта и вклад Phosphor | release-сборка на iPhone, метки времени до/после точечных импортов |
| RTT пользователей из Ингушетии до Beget | `curl -w` с российского мобильного узла или метка времени в приложении |
| Восстанавливается ли ночной дамп | `pg_restore` в отдельный контейнер на VDS разработки + контрольные SELECT |
| Продолжается ли интроспекция PostgREST из `pg_stat_statements` | сброс статистики (действие записи — по слову владельца) и замер через сутки |
| Совпадает ли `src/types/database.ts` с live-схемой | генерация типов из live и diff |
| Намерение владельца по видимости номера `phone_open` для гостя | вопрос владельцу (§5) |
| Откуда в live 3 функции без исходника | `pg_get_functiondef` для каждой и поиск в истории Git (`git log -S`) |

Внешних действий не выполнялось: ни commit, ни push, ни deploy, ни записи в
базу или конфиги. Временные файлы замеров — только в scratchpad сессии.
