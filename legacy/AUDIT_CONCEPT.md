# АУДИТ КОНЦЕПЦИИ xtrud

> Жёсткий аудит концепт-документа маркетплейса услуг для Республики Ингушетия. Без воды. Цель — найти то, что сломает продукт ещё на старте.

---

## РАЗДЕЛ 1. ГЛАВНЫЕ РИСКИ (ТОП-4)

### Риск 1. Cold start проблема двустороннего маркетплейса
**Что сломается.** Двусторонние маркетплейсы умирают от нехватки одной стороны. У вас нет рычага платных мастеров (как у Profi.ru), нет рычага платных клиентов. Бесплатно для всех означает: первые 200 мастеров регистрируются, видят 0 заявок за неделю, уходят. Первые 500 клиентов создают заявку, получают 0 откликов, уходят. Платформа становится "кладбищем профилей".

**Вероятность:** 90%. Это случается с каждым маркетплейсом без явной стратегии cold start.

**Что делать.**
- На старте имитировать вторую сторону руками: автор и амбассадоры собирают вручную 50-100 готовых мастеров до запуска для клиентов; либо публикуют 30-50 реальных заявок из локальных чатов (с согласия) до запуска для мастеров.
- Начать с ОДНОЙ ниши (например, отделочные работы в Магасе/Назрани), не с 38 категорий. Сфокусировать density.
- Платформа должна стать "видимой" в локальных Telegram-каналах до того, как откроется регистрация.

### Риск 2. Монетизация рекламой при 100k MAU невозможна, при 5k MAU — иллюзорна
**Что сломается.** В документе монетизация описана как "стройбазы, банки, страховые". Реальность: рекламодателю нужно либо много трафика (10-100k DAU), либо узкий релевантный B2B-таргет. Локальная стройбаза в Ингушетии не будет платить за рекламу в приложении с 500 DAU — она просто положит свою визитку у мастера. Партнёрские CPA-программы дают деньги только при больших объёмах конверсий, которые на 500-2000 мастеров нерентабельны.

**Вероятность:** 95%. Реклама как монетизация работает у Avito (40M MAU), не у локального сервиса.

**Что делать.**
- Признать: первые 2-3 года денег с проекта не будет вообще. Это волонтёрский/имиджевый проект. Бюджет работы сервера и доменов — из кармана автора, иначе закрывается.
- Альтернативные модели на будущее: подписка для мастеров (от 200 ₽/мес после порога), процент со сделки в защищённом режиме, верификация платная (после первой работы 2-3 платные звезды).
- НЕ строить инфраструктуру для рекламы (кабинет рекламодателя, биллинг) на старте — это месяцы работы соло, которые сгорят впустую.

### Риск 3. Соло-разработчик не реализует объём 🔴-фич за 6-12 месяцев
**Что сломается.** В PROJECT_MAP.md под 🔴 ("без этого продукта нет") стоит примерно 60-70 фич, включая чат с фото/видео/гео, push на iOS+Android+web, ручную модерацию профилей, 13 категорий, верификацию по 5 уровням, web-зеркало приложения, админку с очередями модерации. Это работа продуктовой команды на 12-18 месяцев. Соло за 6-12 месяцев — нереально без массивного сокращения.

**Вероятность:** 99%.

**Что делать.**
- Жёстко переопределить MVP: одна роль (мастер регистрируется, клиент создаёт заявку), одна категория, один город, один экран отклика. Без чата (использовать прямой звонок при открытом номере, или Telegram deep-link). Без web (только mobile или только web в 1-й фазе). Без админки (модерация через Supabase Studio + личный Telegram-бот).
- Раздел 7 ниже даёт перенарезку приоритетов.

### Риск 4. Supabase free tier выгорает на медиа за 1-2 месяца
**Что сломается.** Free tier Supabase Storage = 1 ГБ, bandwidth = 5 ГБ/мес. Один мастер по PROJECT_MAP может загрузить 30 фото + видео-визитку 60 сек + аватар = ~100-200 МБ. 500 мастеров = 50-100 ГБ. Плюс портфолио в заявках. Storage Pro tier = $25/мес за первые 100 ГБ. Bandwidth — отдельная статья. Realtime/Edge functions/auth тоже квотированы.

**Вероятность:** 100%, как только пойдёт рост.

**Что делать.**
- Не хранить оригиналы — сжимать клиентом до 1280px JPEG ~150 КБ перед загрузкой. Видео — на YouTube unlisted, не на Supabase.
- Использовать Cloudflare R2 (бесплатно egress) или Backblaze B2 ($6/ТБ) для медиа вместо Supabase Storage.
- Ограничить мастеру 10 фото в портфолио на старте, не 30+.
- Считать unit-экономику медиа на 1 мастера сразу.

## РАЗДЕЛ 2. ПРОТИВОРЕЧИЯ И НЕДОДУМАННЫЕ СЦЕНАРИИ

1. **"Бесплатно для всех" vs §3.2 "Платный топ для мастера"**
   В §3.3 декларируется "реклама не блокирует функционал", а в §3.2 уже допускается платный топ за 100-300 ₽/неделю. Это прямое нарушение исходного принципа и разрушает доверие мастеров, которым обещали бесплатность. Решить: либо честно говорить "бесплатно + опциональный буст", либо убрать буст совсем.

2. **Маскированные звонки помечены 🟡, но §5.3 объявляет скрытие телефона "главным отличием от Avito"**
   Если скрытие телефона — ключевой UX, маскированные звонки должны быть 🔴. Иначе на старте телефон скрыт, но позвонить нельзя — и клиент с мастером всё равно уходят в Telegram обходом, разрушая контур платформы. Решение: либо принять обход в мессенджер как фичу (deep link), либо вкладываться в Voximplant с первого дня.

3. **"Один телефон = один аккаунт" vs "Клиент — также мастер должен переключать роль"**
   В §5.13 жёсткое правило, но в карте ролей не описано как один пользователь работает в двух ролях с одного телефона. Сделайте one user → many profiles (role switcher), иначе мастер с другом-клиентом не зарегистрируется.

4. **Отзыв "только после закрытой сделки" vs "сделка нигде не фиксируется в платформе"**
   §5.7: отзыв возможен только если обе стороны нажали "работа выполнена". Но в концепции нет ни оплаты на платформе, ни эскроу, ни обязательного closing — сделка по факту проходит вне платформы. Кто будет нажимать "работа выполнена" через месяц после ремонта? Реалистично — 10-20% отзывов получите. Решение: либо ввести напоминание-бот через 7/14/30 дней, либо разрешить отзыв с meta-проверкой (был чат + был обмен номерами).

5. **Тейп/род поле — "опционально, спорно"**
   §5.8 предлагает тейп как опциональное поле. На Кавказе это либо ОЧЕНЬ хорошо работает (мгновенное доверие), либо ОЧЕНЬ плохо (фактор дискриминации при найме). Решение: убрать совсем; вместо этого — мягче, через "село/район" и "поручительства". Никогда не делать публичным.

6. **§5.6 "Перевод сообщений на ингушский ⇄ русский (AI)"** помечено 🟢
   У ингушского языка нет промышленных моделей перевода (нет в Google Translate, нет в Yandex, нет в DeepL). LLM (GPT-4) делают это плохо. Это не "опционально на будущее" — это "невозможно" в текущем состоянии моделей. Убрать или пометить "research project".

7. **Видеозвонок в чате (§5.6, 🟢)** — это серьёзная инфраструктура (LiveKit/Daily/Agora — платные). Не "опционально", а "не на этом проекте никогда". Удалить, не плодить иллюзий.

8. **§5.5 "ИИ-фильтр против шаблонов 50 раз"** требует либо OpenAI API ($), либо embeddings-инфраструктуры. Реальное решение: rate limit на отклики (5 в час) + ручная проверка топ-10 жалоб в неделю. ИИ-фильтр на старте — не нужен.

9. **§5.2 "проверка ИНН"** — публичного автоматического API для проверки статуса самозанятого нет. Скорее всего на старте — ручная сверка скриншота. Документ создаёт иллюзию автоматизации.

10. **§4.4 "Кабинет рекламодателя" с биллингом (🟡)**
    Биллинг = принимаете деньги юрлиц. Это контракты, эквайринг (~2.5% комиссии), бухгалтерия. Соло невозможно. На старте — ручные продажи рекламы (договор оффлайн), интеграция баннеров через config-файл.

11. **§5.7 "Отзыв только после закрытой сделки" vs §5.13 "защита от фейковых отзывов от родственников"**
    Привязка к ID сделки не спасает: мастер договорится с другом, "проведёт" фейковую сделку, попросит отзыв. Реально это ловится только: (а) первый отзыв не публикуется N дней, (б) IP/device fingerprint совпадения, (в) шаблонный текст.

12. **§5.4 шаг 6 "точный адрес виден только выбранному мастеру"**
    Что значит "выбранному"? До выбора мастер не видит адрес → не может оценить выезд → не может назвать цену. Это противоречит §5.5 "цена точная/после осмотра". Решение: показывать улицу/район всем откликнувшимся, точный номер дома — после согласия клиента в чате.

13. **§5.9 "Автоблокировка пятницы 12:00-14:00 (намаз)"**
    Время намаза смещается ежедневно (солнечный календарь). Захардкоженные 12:00-14:00 — этнографически неверно. Использовать API типа aladhan.com или дать ручную настройку.

## РАЗДЕЛ 3. EDGE CASES, КОТОРЫХ НЕТ В PROJECT_MAP

1. **Мастер пропал после получения предоплаты.** Платформа НЕ держит деньги, но клиент пришёл с претензией в чат поддержки. У вас нет процедуры спора. Нужно: SLA на ответ, кнопка "Открыть спор", шаблон выгрузки чата для подачи в полицию.

2. **Клиент не отвечает в чате месяц.** Заявка висит, мастер не понимает закрыта она или нет. Нужно: автозакрытие заявок через 14/30 дней без активности, статус "клиент не вышел на связь".

3. **Мастер и клиент — родственники, фейк-отзыв.** Не упомянуто. Признаки: общие контакты в записной книге, одно устройство в истории auth, одинаковый IP/Wi-Fi. Минимум — задержка публикации первого отзыва 7 дней + ручная проверка.

4. **Мастер выложил чужие фото работ (украл из Instagram).** Очень частый кейс в этом сегменте. Нужно: reverse image search (Google Vision API: $1.50 за 1000 запросов), кнопка "Это моё фото" с upload оригинала + EXIF, банхаммер.

5. **Несовершеннолетний мастер.** Парень 16 лет регистрируется как электрик. Договоры с ним недействительны. Нужно: чекбокс "мне 18+" на регистрации.

6. **Удаление аккаунта самим пользователем.** В iOS App Store с 2022 года это **обязательно** иметь in-app delete account, иначе review reject. Нет в PROJECT_MAP. Добавить в Настройки.

7. **Телефон украден / SIM-swap.** Злоумышленник вошёл в чужой аккаунт мастера, пишет клиентам гадости. Нужно: восстановление через email/Telegram, лог сессий, удалённый logout с других устройств, заморозка аккаунта при подозрительной активности.

8. **Двух мастеров зовут одинаково: "Магомед Х."** Поиск по имени работает плохо. Нужно: deep-link на профиль, человеческий читаемый ID `/m/magomed-ahmadov-magas-3`, не username с дублями.

9. **Мастер сменил категорию.** Был электриком, стал плиточником. Что с отзывами? Старые отзывы — за электрику, новые ищут плиточника. Нужно: либо отзывы привязаны к категории, либо warning "опыт работы в категории X".

10. **Клиент = тоже мастер.** Профессионал кейтеринга заказывает себе клининг. Должен переключать роль одной кнопкой. Не описано.

11. **Заказчик пьян/неадекватен в чате, шлёт оскорбления.** Кнопка жалобы и автомод по матам. Нужен черный список слов + временный mute профиля. Сейчас нет.

12. **По фото невозможно понять задачу.** "Хочу ремонт" + одно мутное фото. Мастер дёрнул, приехал, оказался не тот объём. Нужно: чек-лист обязательных полей по категории (для отделки — площадь, кол-во комнат, состояние стен), либо обязательный fallback "видеозвонок-осмотр".

13. **Мастер шлёт шаблон в 50 заявок за минуту.** Rate limit + ИИ-детект шаблона (мин — Levenshtein/embeddings similarity). Не описано конкретно.

14. **Клиент создаёт фейк-заявку, чтобы выманить телефоны мастеров.** Заявка-приманка → 20 откликов → 20 номеров мастеров → база для холодных продаж/спама. Нужно: количество заявок в день ограничить, требовать видимое участие в чате до получения номеров.

15. **Мастер просит клиента поставить 5 звёзд в обмен на скидку.** Классика. Нельзя предотвратить, но можно сдерживать: статистика "слишком хорошие отзывы" → флаг модерации.

16. **Заказчик-женщина сталкивается с домогательствами в чате.** Гендерный фильтр на мастера ≠ безопасность. Нужно: кнопка "Заблокировать и пожаловаться" + быстрая реакция модерации (часы, не дни) + опция "только женщины" + хранение чата как доказательной базы.

17. **Бан в одной категории — мастер регистрируется на брата.** Sim-карты в регионе легко доступны. Нужно: device-fingerprint, ban по IP/устройству.

18. **Что если пользователь без смартфона / пожилой мастер.** В Ингушетии у части мастеров (50+) только кнопочный телефон + WhatsApp Web через дочь. Сценарий "родственник-агент": один аккаунт ведёт молодой за пожилого. Это нужно ЛЕГАЛИЗОВАТЬ ("представитель мастера"), а не запрещать.

19. **Death case.** Мастер умер. Профиль активен, клиенты пишут, заявки идут. Нужен механизм деактивации по обращению родственника + мемориальный статус.

20. **Природная катастрофа / отключение света на 12 часов.** Заявки в очереди, push не доставляются, мастера не откликаются. Нужно: разумные timeout-ы заявок, ретраи на push, graceful degradation web-версии.

## РАЗДЕЛ 4. ЧТО ПРЕДЛОЖИТЬ ДОБАВИТЬ

1. 🔴 **Soft-launch через закрытый Telegram-канал на 1 категории, 1 город.** Это не фича, это стратегия — но её нужно зафиксировать в документе. Без неё первые 6 мес уходят в пустоту. Сначала 50 мастеров отделки в Магасе, потом всё остальное.

2. 🔴 **Single sign-on через Telegram Login Widget.** Это бесплатно, на порядок проще СМС, и в регионе Telegram = почти 100% покрытие. СМС-OTP стоит ~2-3 ₽ за код у любого провайдера, что при 1000 регистраций в месяц = 2-3 тыс ₽ только на коды. Telegram — 0 ₽.

3. 🔴 **Делетер аккаунта в Настройках + retention policy.** Требование App Store. Без этого приложение не пройдёт ревью.

4. 🟡 **"Открытое портфолио" — публичный профиль мастера без регистрации.** `xtrud.ru/m/имя` для шеринга. Сейчас это 🟢, но это главный SEO-канал + viral-rebrand для мастера ("дай ссылку на портфолио"). Это магнит роста, не "будущее".

5. 🟡 **Шаблонные заявки.** В каждой категории — 5-10 готовых "ремонт квартиры однушка под ключ", "поменять смеситель в ванной", "поклеить обои 20 м²". Клиент в визарде выбирает шаблон → 80% полей заполнены. Резко повышает заполняемость заявок и понятность для мастера.

6. 🟡 **Калькулятор работ в шапке заявки.** "Плитка от 600 ₽/м², 25 м² = 15 000 ₽". Дешёво (статичный JSON), но клиент видит реалистичный диапазон и не пишет "сколько стоит?". Может стать спонсорским размещением.

7. 🟡 **Шеринг визитки мастера.** Когда у мастера ≥3 отзыва — сгенерировать ему "визитку в PDF/PNG" с QR на профиль для шеринга в локальных чатах. Виральный канал #1 в регионе.

8. 🟡 **Поручительство = верифицированный пользователь приглашает мастера по реферальной ссылке.** В концепции это разные фичи. Объединить: реферал автоматически = поручитель. Это запускает социальный граф без отдельного UX.

9. 🟡 **"Совет от соседей" — структурированные ответы на типовые вопросы клиентов.** Не статьи, а UGC: 5 коротких ответов мастеров на "сколько стоит залить фундамент 10×10 в Ингушетии в 2026". Очень дешёво, SEO-золото.

10. 🟢 **Безопасный чат-режим для женщин:** автоматическое предупреждение мастеру "клиент-женщина, общайтесь корректно", автомод по списку слов, быстрая жалоба с эскалацией в Telegram админу за 5 минут.

11. 🟢 **NPS-опрос через 7 дней после закрытия сделки.** Простой вопрос "0-10, насколько рекомендуете?". Это не отзыв, это внутренняя метрика для retention.

12. 🟢 **Локальная "доска объявлений" мастеров — мастер сам создаёт оффер.** Не клиент пишет заявку, а мастер постит "Бригада из 4 человек, готовы взять отделку в Сунже на октябрь, цена от 4500/м²". Симметрия маркетплейса увеличивает плотность контента в 2 раза без дополнительных клиентов.

## РАЗДЕЛ 5. ЧТО УБРАТЬ ИЛИ УПРОСТИТЬ

1. **38 категорий → 5 на старте.** Стройка/отделка, сантехника, электрика, грузоперевозки, бьюти на дому. Это покроет 80% реального спроса в регионе. Остальные открываются по запросу пользователей. Каждая категория = время на иконку, фото, шаблоны, модерацию. 38 — это год работы только над контентом.

2. **5-уровневая верификация → 2 уровня.** ⭐ телефон / ⭐⭐ "видел вживую" (амбассадор или модератор по видеозвонку). Паспорт, ИНН, диплом — выкинуть на год. Это всё ручная работа, которой соло не вывезет, а юзеры не понимают разницу между ⭐⭐⭐⭐ и ⭐⭐⭐⭐⭐.

3. **Web-зеркало приложения в Фазе 1 → только публичные профили мастеров (SEO-лендинги).** Полное web-приложение для всех ролей — двойная работа. На старте: mobile-only для логина/действий, web — только статика для SEO. После 1000 мастеров — пересмотр.

4. **Кабинет рекламодателя → Google Form + ручная вставка баннера в config.** Никаких личных кабинетов с биллингом первый год. Когда наберётся 3-5 платящих рекламодателей — тогда строить.

5. **Видео-визитка, видео-отзывы, видеозвонок в чате → одно: фото + текст.** Видео = огромный storage, плохое UX на медленных мобильных сетях региона, дорого. Через 2 года можно добавить.

6. **Маскированные звонки → Telegram deep-link "Написать в Telegram".** Платформа не показывает номер, но даёт кнопку — мастер пишет в Telegram. Дешевле виртуальной АТС.

7. **Чат внутри приложения → минимальный (текст + 1 фото).** Голосовые, гео-точка, шаблоны, видео — всё после первой 1000 заказов. На старте — текст и фото.

8. **Импорт контактов → нет.** App Store на это смотрит косо. Лучше "пригласить друга по реферал-ссылке".

9. **Многоязычность ингушский / английский / чеченский → только русский на 1-2 года.** Все жители региона свободно владеют русским. Локализация — это ~30% доп. работы и поддержки. Идеологически приятно, практически бесполезно.

## РАЗДЕЛ 6. ТЕХНИЧЕСКИЕ УЗКИЕ МЕСТА

### 6.1. Supabase Storage и квоты
- **Free tier:** 1 ГБ storage, 5 ГБ egress/мес, 50k MAU auth, 500 МБ Postgres, 2 ГБ realtime messages, 500k Edge function invocations.
- **Pro tier ($25/мес):** 100 ГБ storage, 250 ГБ egress, 100k MAU, 8 ГБ Postgres.
- **Реальный расход на 500 мастеров (10 фото × 300 КБ + аватар + 5 фото портфолио × 500 КБ):** ~3-4 ГБ + 5-15 ГБ egress/мес.
- **Вывод:** на free tier хватит на ~100-150 мастеров. После — Pro tier $25 = ~2000 ₽/мес = подъёмно. При 5000 мастеров — уже надо думать о CDN.
- **Рекомендация:** медиа выносить на Cloudflare R2 (бесплатный egress) или Backblaze B2. Supabase Storage оставить только для документов (если будете хранить).
- Видео НИКОГДА на Supabase Storage. YouTube unlisted или Cloudflare Stream.

### 6.2. Маскированные звонки
- **Voximplant:** входящий звонок на свой DID ~5-15 ₽/мин в зависимости от региона. Минимальный DID ~500 ₽/мес.
- **Exolve (МТС):** аналогично, от 0.5 до 2 ₽/мин SIP-аплинк + плата за номер.
- **Zadarma:** дешевле, минут от 3-5 ₽/мин звонок.
- **Реалистично:** 200 звонков в день × 3 мин × 5 ₽ = 3000 ₽/день = 90 000 ₽/мес. На бесплатной модели — невозможно.
- **Альтернатива:** на 1-й год без масок. Кнопка "Открыть номер" — клиент сам решает. Маски — только когда есть монетизация.

### 6.3. Push: Expo vs свой сервер
- **Expo Push Service:** бесплатно, без лимитов на push (rate-limit ~600 за 5 сек, но это много).
- **Своя инфраструктура (FCM + APNs):** бесплатно, но сложнее в setup и поддержке.
- **Рекомендация:** Expo Push первые 6-12 месяцев. Когда упрётесь в их rate-limit (вряд ли) — мигрировать на прямой FCM.

### 6.4. Модерация без бюджета
- **OpenAI Moderation API:** бесплатно (!). Для текста на ru работает прилично. Лимиты — тысячи запросов/мин.
- **Google Vision SafeSearch:** $1.50/1000. Для проверки фото на 18+/насилие.
- **OpenAI GPT-4o-mini для модерации описаний:** ~$0.15/1М input tokens. На каждые 1000 описаний — копейки. Можно делать первичный фильтр.
- **Reverse image search:** Google Vision API $1.50/1000, либо TinEye (платный), либо самописное perceptual hashing (pHash, бесплатно). На старте — pHash достаточно для детекта дублей внутри платформы.
- **Рекомендация:** OpenAI Moderation + pHash на старте. ~500 ₽/мес максимум. Ручная финальная модерация автором через Supabase Studio + Telegram-бот.

### 6.5. Реалистичность поддержки соло
- **Объём кода Фазы 1 (все 🔴):** при честной оценке — 80-120 экранов мобильного + 20-30 экранов web + админка + бэкенд логика. Это 8-14 месяцев работы соло-разработчика на full-time. Если "для души" в свободное время (10-15 ч/неделю) — 24-36 месяцев.
- **Поддержка:** после запуска 500 мастеров минимум 3-5 ч/день уходит на модерацию, поддержку, фиксы. Это второй full-time.
- **Вывод:** соло невозможно вытянуть полный 🔴 PROJECT_MAP. Либо сокращение MVP в 5-10 раз, либо команда (хотя бы 1 модератор + 1 community manager на полставки = ~30-50 тыс ₽/мес).

## РАЗДЕЛ 8. ЕСЛИ БЫ ДЕЛАЛ Я (МАНИФЕСТ)

Бюджет 0, соло, цель — 100 мастеров за 6-12 месяцев. Делал бы так.

**Месяцы 1-2: НЕ пишу код.** Создаю Telegram-канал "Мастера Ингушетии — отделка". Лично хожу по объектам в Магасе/Назрани, фотографирую готовые работы 30-50 мастеров, договариваюсь о размещении. Канал растёт до 1000 подписчиков. Это будущая аудитория. Параллельно — Google Form для подачи заявки клиентом, я вручную форвардю заявки мастерам. Зрелые маркетплейсы (Profi.ru, Thumbtack) все так начинали — концирж-MVP.

**Месяцы 3-5: пишу minimum mobile app.** Один экран мастера (регистрация через Telegram Login), один экран клиента (заявка). Чат — Telegram deep-link с маскированием через виртуальный номер позже. Storage — Cloudflare R2. БД — Supabase free. Никакой админки — модерация через прямой Telegram-DM. Push — Expo Push. Одна категория — отделка. Один город — Магас/Назрань. Web — статичная landing на vercel с публичными профилями мастеров для SEO.

**Месяцы 6-8: запуск в Telegram-канал.** 1000 подписчиков → 100-200 регистраций мастеров → 30-50 активных. Клиенты — из того же канала + сарафан. Метрика — % заявок, по которым была реальная сделка (трекать руками в Notion).

**Месяцы 9-12: расширение по запросу.** Если работает: + сантехника, + грузоперевозки. Если не работает на одной категории — закрыть, не насиловать. Тогда же — донаты СБП, первый рекламодатель (локальная стройбаза, договор на бумаге, 5-10 тыс ₽/мес за баннер).

**Чего НЕ делаю первый год:** видео, голосовые, маски звонков, многоязычность, тейп-фильтры, чат-видеозвонок, кабинет рекламодателя, ИНН-проверки. Всё это — 13-й месяц минимум.

**Главный принцип:** product-market fit в одной категории + одном городе важнее, чем 38 категорий в 5 городах. Если не получится продать ремонт через сервис в Магасе — не получится и в Малгобеке.
