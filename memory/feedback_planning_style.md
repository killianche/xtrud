---
name: Стиль работы над концепцией — не резать, помечать приоритеты
description: Пользователь хочет видеть все варианты функционала, без вырезания, с маркировкой важности
type: feedback
---

Пользователь явно сказал: "ничего не резать никогда. Предлагать все варианты по списку, указывая какие важнее какие менее".

**Why:** Пользователь составляет концепт-документ, а не план разработки. Ему важно видеть полную картину возможностей, а не "минимально жизнеспособный продукт". Решения о сокращении он будет принимать сам, позже.

**How to apply:**
- Не предлагать "вырезать из MVP" — вместо этого помечать ярлыками приоритета: 🔴 критично / 🟡 важно / 🟢 опционально-будущее.
- Давать развёрнутые списки фич, экранов, опций.
- Не уговаривать на "быстрый запуск". Цель — карта проекта, а не запуск.
- Не обсуждать сроки/команду/бюджет, если пользователь сам не поднимет.
- Работа происходит в чате с нейросетью; код не пишется.
